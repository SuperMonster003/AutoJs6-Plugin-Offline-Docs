调试脚本 (Debug Scripts)#

自 AutoJs6 6.8.1 起, 可以用两种方式调试脚本:

  • 代码编辑器内调试: 编辑器菜单中的 "调试", 不需要电脑与插件.
  • 远程调试: 安装 3-Probe Debugger 插件后, 在电脑上用 VS Code, JetBrains IDE, Neovim 等支持 Debug Adapter Protocol (DAP) 的编辑器调试设备上的脚本.

本页面介绍远程调试. 本页面不是脚本 API; 脚本得知自身是否正被调试, 等待调试器附加的方法见 调试 (Debugging).

准备#

  • AutoJs6 6.8.1 (内部版本 6641) 或更高版本, 以及 3-Probe Debugger 1.0.0 或更高版本. 在插件中心启用插件, 并在主页抽屉中打开 "调试服务", 见 安装与启用.
  • TypeScript 脚本需要 TypeScript 编译插件 (TypeScript Engine); Node.js 脚本需要 Node.js 运行时插件 2.2.0 或更高版本.
  • 电脑能到达手机: 数据线与 adb, 同一局域网, 或 AutoJs6 的开发连接, 见 连接方式.

脚本按文件名决定在哪个引擎上运行:

文件 引擎
.js Rhino
.ts, .tsx (不含 .d.ts) 由 AutoJs6 编译后在 Rhino 上运行, 断点与单步按源映射落在 .ts 源码上
.node.js, .mjs, .cjs, .mts, .cts, Node.js 项目 Node.js

单个 .ts 文件不能作为 Node.js 脚本调试 (与普通运行一致); Node.js 的单文件 TypeScript 请用 .mts 或 .cts, .ts 放进 Node.js 项目.

三种开始方式#

  • 启动 (launch): 由电脑启动脚本并调试. 脚本可以是电脑上的文件 (文本随启动发送到设备, 设备上不需要有该文件), 设备上的文件, 或保存到设备的项目.
  • 附加 (attach): 附加到正在运行的脚本. 只有在调试服务开启之后开始运行的 Rhino 脚本可以附加, 见 可附加的条件.
  • 等待调试器: 让脚本启动后先等调试器附加, 再开始运行.
    • 在代码编辑器的菜单或文件管理器中脚本的选项菜单中选择 "调试运行". 脚本先等待调试器附加 (对话框显示剩余时间), 附加后在调试器完成设置时开始运行; 等待超时后脚本照常运行, 不调试. 对话框中的 "直接运行" 不等待. 只有在 Rhino 引擎上运行的脚本可以调试运行.
    • 在脚本中调用 debugging.waitForAttach.
    • 然后在电脑上用附加配置并设置 waitForTarget: true, 调试器附加到正在等待的脚本或下一个启动的脚本.

VS Code#

需要 AutoJs6 VSCode 扩展 1.2.0 或更高版本.

  1. 用扩展与设备建立连接 (任一种方式均可). AutoJs6 默认随开发连接开启调试服务, 未开启时 VS Code 会自动开启.
  2. 开始调试 (任选其一):
    • 点击编辑器标题栏的 "调试脚本" 按钮, 或在资源管理器中右键脚本文件选择该命令.
    • 没有 launch.json 时按 F5 直接调试当前文件; VS Code 询问使用哪个调试器时选择 "AutoJs6".
    • 在 launch.json 中添加 "AutoJs6: 调试当前文件", "AutoJs6: 调试项目" 或 "AutoJs6: 附加到脚本" 配置.
  3. 脚本来源:
    • 单个文件: 编辑器中的文本 (包括未保存的修改) 随启动发送到设备.
    • 项目 (含 project.json 的目录): 先像 "保存项目到设备" 那样保存到设备, 再调试设备上的副本; 断点 (包括 require 的模块中的断点) 对应回本地文件.
    • 设备文件: 在 "设备文件" 视图中打开的 autojs6fs:// 文件可以直接设置断点并调试.
  4. 调试通道由调试配置的 transport 决定, 默认 auto: 经 USB (ADB) 连接的设备自动执行 adb forward, 经局域网连接的设备直接连接 <手机地址>:8347 (监听范围要设为局域网), 直连不可用时改用开发连接隧道.
{
    "version": "0.2.0",
    "configurations": [
        { "type": "autojs6", "request": "launch", "name": "Debug current script", "program": "${file}", "stopOnEntry": false },
        { "type": "autojs6", "request": "launch", "name": "Debug project", "project": "${workspaceFolder}" },
        { "type": "autojs6", "request": "attach", "name": "Attach to a running script", "waitForTarget": true }
    ]
}
  • 条件断点, 命中次数断点, 日志点, 异常断点 (全部 / 未捕获), 修改变量值, 监视, 悬停求值与调试控制台中的求值 (带自动补全) 均可使用. 悬停只显示简单表达式的值, 不调用 getter; 调试控制台求值期间不会停在断点.
  • 子脚本: 被调试脚本用 engines.execScript / engines.execScriptFile 启动的脚本默认在同一会话中调试, 线程显示为 "脚本 / 线程", 断点同样生效; debugChildScripts: false 关闭. childSessions: true 时每个子脚本有自己的调试会话 (经隧道时不可用, 不可用时改为并入并在调试控制台说明原因).
  • 经局域网调试时, 第一次需要在手机上确认, 见 配对密钥与令牌. 扩展把配对密钥保存在 VS Code 的机密存储中; 命令 "忘记手机的调试配对密钥" 删除它, "选择调试设备" 更改本工作区调试时使用的设备.

Node.js 脚本#

  • 启动后脚本先在第一行等待调试器. VS Code 自动附加其自带的 JavaScript 调试器 (js-debug), 作为 AutoJs6 调试会话的子会话; 断点, 单步, 调用栈与变量的用法与调试本机的 Node.js 程序相同. 调试控制台显示中继的连接地址.
  • 调试器经插件的 Node.js 中继端口 (默认 8348) 连接. 经数据线时转发该端口 (adb forward tcp:8348 tcp:8348, VS Code 扩展自动完成); 没有 ADB 时 (局域网直连或隧道), 电脑经局域网连接手机的 8348, 因此监听范围要设为局域网.
  • 规定时间 (默认 30 秒) 内没有调试器连上时脚本结束, 不运行. 脚本结束后中继自动断开调试器.
  • TypeScript 源文件 (.mts, .cts 与 Node.js 项目中的 .ts) 中的断点经源映射对应回源文件. 电脑上的文件文本随启动发送到设备时, 以同名文件运行, 断点同样按文件对应.
  • 已在运行的 Node.js 脚本不能附加, 只能以调试模式启动.
  • 电脑设置了 HTTP 代理 (例如环境变量 HTTP_PROXY) 时, 调试器经局域网访问中继的请求可能被代理拦下并返回 503, 此时把手机地址加入不走代理的列表 (例如 NO_PROXY).
  • 其他 DAP 客户端需要自行配置 Node.js 调试器 (Chrome DevTools Protocol) 连接中继端口.

调试配置#

VS Code 的 launch.json 与通用 DAP 客户端的 launch / attach 参数使用同一组属性:

属性 请求 类型与默认值 说明
program launch 字符串 电脑上的文件 (启动时一并发送其文本), 设备文件 (autojs6fs://) 或设备上的绝对路径
project launch 字符串, 可选 电脑上的 AutoJs6 项目目录: 先保存到设备, 再以其入口启动, 并自动设置 localRoot / remoteRoot (VS Code 扩展)
engine launch auto / rhino / node, 默认 auto 运行引擎, auto 按文件名判断 (VS Code 扩展)
stopOnEntry launch 布尔, false 在脚本的第一行暂停
targetId / targetName attach 字符串, 可选 要附加的脚本 (id 或名称); 都省略时附加最新启动的脚本
waitForTarget attach 布尔, false 没有匹配的脚本时, 等待下一个启动的脚本 (正在 "调试运行" 中等待的脚本也算)
waitTimeoutMs attach 整数, 默认与上限 600000 waitForTarget 的等待时长 (毫秒)
localRoot / remoteRoot 两者 字符串, 可选 电脑上的目录与它对应的设备目录, 两者同时给出才生效
pathMappings 两者 数组, 可选 [{ "localPath": "...", "remoteName": "..." }]: 电脑上的单个文件与它在 AutoJs6 中的源名 (设备路径, 或没有文件的脚本的名称)
justMyCode 两者 布尔, true 单步与调用栈中略过 AutoJs6 的内部模块
stopAllThreads 两者 布尔, true 一个线程暂停时, 同时暂停脚本的其他线程
uiThreadPauseTimeoutMs 两者 整数, 60000 UI 线程暂停超过这么多毫秒后自动继续, 0 为不自动继续
debugChildScripts 两者 布尔, true 在本会话中一并调试 engines.execScript / execScriptFile 启动的脚本
childSessions 两者 布尔, false 每个子脚本一个独立的调试会话 (需要客户端支持, 经隧道时不可用)
device 两者 字符串, 可选 设备 id 或名称 (VS Code 扩展)
host / port 两者 可选 手动指定 DAP 地址, 跳过 VS Code 扩展的自动引导
transport 两者 auto / tcp / tunnel, 默认 auto VS Code 扩展到达设备的方式
token 两者 字符串, 可选 插件开启令牌模式时的令牌
pairingKey 两者 字符串, 可选 局域网配对密钥, 见 配对密钥与令牌
terminateOnDisconnect 两者 布尔, launch 为 true, attach 为 false 调试器断开时是否结束脚本

通用 DAP 客户端#

不带 AutoJs6 专用扩展的 DAP 客户端以 TCP 方式连接插件的 DAP 端口:

  1. 经数据线时先在电脑上执行 adb forward tcp:8347 tcp:8347, 客户端连接 127.0.0.1:8347; 经局域网时把插件的监听范围设为局域网, 客户端连接 <手机地址>:8347.
  2. 把脚本放到设备上 (例如 VS Code 扩展的 "保存到设备", 或 adb push), 在电脑上保留同样内容的副本, 用 localRoot / remoteRoot 把电脑上的目录对应到设备目录, 断点设在电脑上的副本里.
  3. 用附加配置并设置 waitForTarget: true, 开始调试后在手机上运行脚本; 或让脚本调用 debugging.waitForAttach, 或用 "调试运行" 启动它. 也可以用 launch 并把 program 设为设备上的绝对路径.

Neovim (nvim-dap)#

以下配置已用 Neovim 0.12.6 与 nvim-dap 0.10.0 实测 (Android 9 设备, 经 adb forward):

-- adb forward tcp:8347 tcp:8347
local dap = require("dap")
dap.adapters.autojs6 = { type = "server", host = "127.0.0.1", port = 8347 }
dap.configurations.javascript = {
    {
        type = "autojs6",
        request = "attach",
        name = "AutoJs6: attach",
        waitForTarget = true,
        localRoot = "/path/to/scripts",
        remoteRoot = "/sdcard/Scripts",
        -- pairingKey = "...", -- after "allow and remember" on the phone, for LAN connections
    },
}

在电脑上打开 /path/to/scripts 中的脚本, 用 :lua require("dap").toggle_breakpoint() 设置断点, :lua require("dap").continue() 选择 "AutoJs6: attach" 开始等待, 然后在手机上运行 /sdcard/Scripts 中的同名脚本. 停在断点后可以用 nvim-dap 的界面查看调用栈与变量.

JetBrains IDE (LSP4IJ)#

AutoJs6 JetBrains 插件将提供专用的调试配置; 在此之前可以用 LSP4IJ 插件的通用 DAP 运行配置附加 (已用 LSP4IJ 0.21.0 与 IntelliJ IDEA 2025.2 实测):

  1. 安装 LSP4IJ 插件.
  2. 菜单 Run > Edit Configurations..., 添加 "Debug Adapter Protocol" 配置.
  3. Server 页: Name 填 AutoJs6 等名称, Command 留空.
  4. Mappings 页: 添加 File name patterns *.js (以及 *.ts 等要设断点的文件), 否则编辑器不允许在这些文件中设断点.
  5. Configuration 页: Debug Mode 选择 Attach, Address 填 127.0.0.1 (经局域网时填手机地址), Port 填 8347; DAP parameters (JSON) 的 Attach 页填写:
{
    "type": "autojs6",
    "request": "attach",
    "name": "AutoJs6: attach",
    "waitForTarget": true,
    "localRoot": "C:\\path\\to\\scripts",
    "remoteRoot": "/sdcard/Scripts"
}
  1. 在脚本中设置断点, 以 Debug 方式运行该配置, 然后在手机上运行同名脚本.

IntelliJ IDEA Ultimate, WebStorm 等自带 JavaScript 调试的 IDE 中, 同一行只能放一种断点, 而自带的 JavaScript 断点总是优先, 在行号栏点出的都是 JavaScript 断点. LSP4IJ 只发送自己的 "DAP Breakpoint", 于是附加成功后脚本不会停下, 一直运行到结束. 在这类 IDE 中, 先在 Settings > Plugins 中停用 "JavaScript Debugger" 插件 (连同依赖它的插件) 并重启 IDE, 再重新设置断点; 停用后该 IDE 自带的 JavaScript 与 Node.js 调试也不可用. 不带 JavaScript 调试插件的 IDE (例如 Android Studio) 不受影响.

配对密钥与令牌#

  • 经局域网连接时, 一台电脑第一次 launch / attach 之前手机会询问, 见 安全. 在手机上选择 "允许并记住" 后, 通用 DAP 客户端的调试控制台显示一行:
3-Probe Debugger: the phone remembered this computer. Add "pairingKey": "..." to this launch / attach configuration; with it the phone lets this computer in without asking, also from another address. Keep it like a password.
  • 把其中的 "pairingKey": "..." 抄进调试配置 (nvim-dap 写作 pairingKey = "..."), 之后这台电脑即使换了地址, 手机也不再询问. 在插件中撤销这台电脑后密钥失效, 手机会重新询问.
  • 局域网客户端在 launch / attach 放行之前发出的其他请求会被拒绝, 提示先 launch 或 attach.
  • 插件开启令牌模式时, 在调试配置中填写 token (插件设置中可复制), 手机不再询问, 配对密钥不再使用.

已知限制#

  • 代码编辑器内调试时, UI 线程 (如 "ui" 脚本的主体与界面事件回调) 停下后立即自动继续: 编辑器本身运行在 UI 线程上, 因此编辑器提示停下的位置, 但无法在该处查看变量. 调试 UI 线程上的代码请使用远程调试器, 见 UI 线程上的暂停.
  • 远程调试器可以让 UI 线程停下并查看变量, 但暂停期间应用无响应, 默认至多 60 秒后自动继续 (uiThreadPauseTimeoutMs).
  • Node.js 的 ES 模块入口 (.mts, .mjs 文本) 与 Node.js 项目的 TypeScript 入口: 从入口暂停单步时, 可能在第一条语句上再停一次才离开首行 (最多多停一次). 这是 V8 入口暂停的位置决定的, 断点与首次暂停的位置不受影响.
  • 单个 .ts 文件不能作为 Node.js 脚本调试, 见 准备.
  • 调试服务开启之前已在运行的脚本, 打包应用中的脚本, 以及已在运行的 Node.js 脚本不能附加.

性能#

调试服务开启期间新启动的 Rhino 脚本都带调试钩子, 即使没有附加调试器. 以下为 Android 9 设备 (Sony G8441) 上 debug 构建的实测, 与不带调试钩子时同进程比较:

场景 耗时
纯 JavaScript 的函数调用密集计算 约 +50% - 57%
纯 JavaScript 的循环 约 +25% - 29%
图像处理 无明显变化
控件查找 约 +4%
脚本启动 增加不到 2 ms
  • 热循环中的条件断点每次到达都要求值条件 (每次约 1.6 - 1.9 us), 循环约为不挂调试器时的 4 - 5 倍. 可以改用命中次数断点, 或把断点移到循环之外.
  • 关闭调试服务后, 新启动的脚本不带调试钩子, 耗时与不调试时相同; 调试会话结束后不留下额外的负担.
