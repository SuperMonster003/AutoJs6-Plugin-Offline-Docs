写出器对象 (Writer)#

运行时支持 Rhino Node.js 主线程 Node.js Worker Bun
入口 Writer 对象 autojs6:xlsx autojs6:xlsx host.xlsx
状态 已支持 13 项 已支持 13 项 已支持 13 项 需授权 13 项
授权 - - - xlsx.control 13 项

各 API 在同一运行时中的入口, 状态与授权一致, 没有差异项.

Node.js 与 Bun 的导入方式, 异步返回值与授权检查见 运行时 API.

Writer 是 xlsx.createWriter 返回的写出器对象, 用于逐行生成很大的 xlsx, csv 或 tsv 文件. 插件只在内存中保留最近写出的 100 行, 内存占用与行数无关.

每个方法都有同步形态与 Async 形态, 参数与结果一致, 规则同 xlsx 模块; 其中只有 closeAsync 报告进度. 失败时抛出 (或拒绝为) XlsxError, 与单元格有关时错误的 sheet 与 ref 指出位置.

写出的内容先进入临时文件, 调用 close 成功后文件才出现在目标路径, 目标路径上已有的文件被替换. 调用 abort, close 失败或脚本结束 (含被停止) 时丢弃已写的内容, 目标路径上已有的文件保持不变.

行的写法:

  • 数组行从第 1 列开始写.
  • 对象行按工作表的表头列名取值, 没有对应键的列留空, 表头里没有的键被忽略. 工作表没有给出表头列名时, 按第一个对象行的键的顺序取值; 此时工作表仍为空, 并且 header 不为 false 的, 这些键先写为表头行.
  • 单元格的值与日期见 行列编号与数据模型, 单元格对象 { v, f, style } 的 style 只接受 StyleSpec. 写出器不接受 formulas 与 dateFormat 选项: 以 = 开头的字符串写为文本, 公式写作 { f: '...' } 对象; 日期的数字格式为 yyyy-mm-dd hh:mm:ss.
  • 公式在写出时检查语法 (错误时失败于 FORMULA_ERROR), 但不计算, 文件被设置为打开时重算.
  • csv 与 tsv 没有样式与公式: 样式被忽略, 公式对象写出其 v, 并在结果的 warnings 中说明.
let w = xlsx.createWriter('./report.xlsx', { sheet: '一月', header: ['日期', '金额'] });
try {
    w.addRows([[new Date(2026, 0, 1), 120], [new Date(2026, 0, 2), 98]]);
    w.addSheet('二月', { header: ['日期', '金额'], freeze: { rows: 1 } });
    w.addRow([new Date(2026, 1, 1), 133]);
    w.addRow(['合计', { f: 'SUM(B2:B2)' }], { style: { font: { bold: true } } });
    console.log(w.toString()); // Writer { format: xlsx, rowCount: 4 }
    let r = w.close();
    console.log(r.sheets.map(s => s.name + ': ' + s.rows).join(', ')); // 一月: 3, 二月: 3
} catch (e) {
    w.abort();
    throw e;
}

Writer

[@] Writer#

6.8.1

写出器对象. 不能用 new 构造, 只由 xlsx.createWriter 与 xlsx.createWriterAsync 产生. 创建时已开始写第一个工作表 (名称为选项 sheet, 默认 'Sheet1').

写出器占用一个句柄 (每个脚本与打开的工作簿合计至多 16 个), close 或 abort 后释放. 插件 30 分钟没有收到写出器的调用时关闭它并丢弃已写的内容 (缓冲中的 addRow 不发送到插件, 不算调用), 此后发往插件的调用失败于 SESSION_CLOSED. 调用 close (无论成功与否) 或 abort 之后, 除 abort 外的调用都立即失败于 SESSION_CLOSED (消息形如 "the writer is closed"), 不带 style 的 addRow 也不例外, rowCount 不再变化.

[p#] format#

6.8.1

  • { 'xlsx' | 'csv' | 'tsv' }

输出格式, 取选项 format, 其次取目标的扩展名. 只读.

[p#] rowCount#

6.8.1

  • { number }

已添加的数据行数: 所有工作表合计, 不含表头行, 包括尚在缓冲中的行. 只读, 每次读取都反映当前的值.

close 结果中各工作表的 rows 为最后一个有内容的行号, 含表头行, 因此与 rowCount 不同.

[m#] addSheet#

w.addSheet(name, options?)#

6.8.1

  • name { string } - 新工作表的名称
  • [ options ] {{
    • header?: boolean | string[];
    • columnWidths?, freeze?, autoFilter?: 见 LayoutOptions;
  • }} - 工作表选项
  • returns { void }

结束当前工作表, 开始写名为 name 的新工作表, 之后添加的行写入新工作表. 已结束的工作表不能再写入.

  • 只用于 xlsx: csv 与 tsv 只有一个工作表, 失败于 UNSUPPORTED (消息形如 "a csv file holds one sheet").
  • name 为 1 至 31 个字符, 不能含有 /, ?, *, [, ], : 与反斜杠, 不能以单引号开头或结尾, 不能与已有的工作表重名 (不区分大小写), 否则失败于 INVALID_ARGUMENT.
  • header 为字符串数组时, 这些名称立即写为表头行 (至少 1 个, 至多 16384 个, 超出时失败于 LIMIT_EXCEEDED), 对象行按这些名称取值. header 为 false 时不写表头行, 对象行仍按第一个对象行的键的顺序取值. header 为 true 或省略时, 表头行由第一个对象行的键产生.
  • columnWidths, freeze 与 autoFilter 的写法同 LayoutOptions, 作用于新工作表. columnWidths: 'auto' 按写出的前 100,000 行调整列宽, 需要 header 为字符串数组以确定列数, 否则失败于 INVALID_ARGUMENT; 以数组或对象逐列给出 'auto' 时不受此限. autoFilter: true 作用于该工作表最终写出的区域.
w.addSheet('明细', { header: ['编号', '名称', '数量'], columnWidths: 'auto', autoFilter: true });
w.addRow({ 编号: 1, 名称: '钢笔', 数量: 3 });

[m#] addRow#

w.addRow(row, options?)#

6.8.1

  • row { any[] | object } - 一行, 数组或对象
  • [ options ] {{
    • style?: StyleSpec;
  • }} - 行选项
  • returns { void }

向当前工作表添加一行. row 不是数组或对象时失败于 INVALID_ARGUMENT.

  • 不带 style 时, 行先在 AutoJs6 中缓冲, 每满 1000 行一并发送给插件, 其余的在 addRows, addSheet 或 close 之前发送. 因此这些行的错误 (例如公式语法错误, 超出行数上限) 可能在之后的调用中才报告. 缓冲的行分块发送 (每块至多 1000 行, 行的内容较多时更少); 发送中途失败时, 已写出的块离开缓冲, 只有未写出的行留在缓冲中, 由之后的调用再次发送, rowCount 不会重复计入. 错误由行的内容引起时再次发送仍会失败, 放弃写出时请调用 abort.
  • 带 style 时, 先发送缓冲中的行, 再立即发送这一行, 并把样式应用到这一行写出的各个单元格. 每次调用都要与插件往返一次, 比不带样式的调用慢得多; 大量带样式的单元格可以改用单元格对象的 style. style 只接受 StyleSpec, 不接受样式 id. csv 与 tsv 忽略样式.
w.addRow(['合计', { f: 'SUM(B2:B100)' }], { style: { font: { bold: true }, fill: '#FFF2CC' } });

[m#] addRows#

w.addRows(rows)#

6.8.1

  • rows { any[][] | object[] } - 要添加的行
  • returns { void }

向当前工作表添加多行. 先发送 addRow 缓冲中的行, 再把 rows 分块发送, 每块至多 1000 行 (行的内容较多时更少). 每块要么全部写出, 要么 (失败时) 一行也不写出; 失败时此前的块已经写出.

let batch = [];
for (let i = 1; i <= 5000; i++) {
    batch.push({ 序号: i, 平方: i * i });
}
w.addRows(batch);

[m#] close#

w.close()#

6.8.1

  • returns { SheetResult }

发送缓冲中的行, 完成文件并把它移到目标路径, 然后关闭写出器. 结果的 sheets 列出每个工作表的 name, rows (最后一个有内容的行号, 含表头行) 与 cols.

  • password 加密的写出器在此时加密输出.
  • columnWidths: 'auto' 与 autoFilter: true 在各工作表结束时 (开始下一个工作表或关闭时) 应用.
  • 失败时写出器同样关闭, 已写的内容被丢弃, 目标路径上已有的文件保持不变.
  • 关闭后再次调用失败于 SESSION_CLOSED.

[m#] closeAsync#

w.closeAsync(options?)#

6.8.1 Async

  • [ options ] {{
    • onProgress?: (progress: Progress) => void;
  • }} - 进度回调
  • returns { Promise<SheetResult> }

同 close, 并通过 onProgress 报告进度: 阶段为 'save', 总量为所有工作表的行数 (含表头行). 大的 xlsx 在关闭时才把各工作表写入文件, 可能需要较长时间.

w.closeAsync({ onProgress: p => console.log(p.stage, p.percent + '%') })
    .then(r => console.log(r.path, r.sizeBytes))
    .catch(e => console.error(e.toString()));

[m#] abort#

w.abort()#

6.8.1

  • returns { void }

关闭写出器并丢弃已写的内容, 目标路径上已有的文件保持不变. 可以重复调用; close 成功后调用时不做任何事, 已完成的文件保留. closeAsync 进行中调用时, 取消关闭操作.
