调试 (Debugging)#

运行时支持 Rhino Node.js 主线程 Node.js Worker Bun
入口 debugging - - -
状态 已支持 6 项 不适用 6 项 (仅限 Rhino 引擎), 等价写法: the inspector module of Node.js (inspector.url, inspector.waitForDebugger and the Debugger domain of inspector.Session); none in Bun 不适用 6 项 (仅限 Rhino 引擎), 等价写法: the inspector module of Node.js (inspector.url, inspector.waitForDebugger and the Debugger domain of inspector.Session); none in Bun 不适用 6 项 (仅限 Rhino 引擎), 等价写法: the inspector module of Node.js (inspector.url, inspector.waitForDebugger and the Debugger domain of inspector.Session); none in Bun

各 API 在同一运行时中的入口, 状态与授权一致, 没有差异项.

Node.js 与 Bun 的导入方式, 异步返回值与授权检查见 运行时 API.

debugging 模块用于让脚本得知自身是否正被调试, 以及在调试器附加, 分离, 暂停与继续时得到通知. 调试器可以是 AutoJs6 代码编辑器的 "调试", 也可以是经 3-Probe Debugger 插件连接的调试器 (如 VS Code).

此模块只读取调试状态, 不控制调试器: 脚本不能读取断点或变量, 也不能单步执行自己的调试会话.

debugging 与 $debugging 指向同一个模块对象. 此模块仅用于 AutoJs6 脚本 (Rhino 引擎); Node.js 脚本请使用 Node.js 自带的 inspector 模块.

可附加的条件#

只有在调试已开启时开始运行的脚本才能被调试器附加:

  • 在代码编辑器中用 "调试" 运行的脚本, 开始时即已附加.
  • 在主页抽屉开启 "调试服务" (需要 3-Probe Debugger 插件) 之后开始运行的脚本, 可由远程调试器附加, 也可用 "调试运行" 让脚本先等待调试器.

调试服务开启之前已在运行的脚本, 未安装或未启用插件时运行的脚本, 以及打包应用中的脚本, 永远不会被附加. 此时 waitForAttach 等到超时返回 false (未给出超时则立即返回 false), breakpoint 不起作用, 监听器不会被调用.

debugging

[m] isAttached#

isAttached()#

6.8.1

  • returns { boolean } - 是否有调试器附加

判断当前脚本是否有调试器附加 (编辑器或远程调试器).

if (debugging.isAttached()) {
    console.log('正在调试');
}

[m] waitForAttach#

waitForAttach(timeout?)#

6.8.1

  • [ timeout ] { number | null } - 最长等待时间 (毫秒), 不小于 0 的整数; 省略或为 null 时不限时
  • returns { boolean } - 是否有调试器附加

等待调试器附加并结束配置后返回 true. 结束配置即调试器发出 configurationDone, 此时调试器设置的断点已经生效, 脚本继续运行时不会错过随后代码中的断点.

  • 超时后返回此时是否有调试器附加 (已附加但尚未结束配置时也返回 true).
  • 脚本不可附加 (见 可附加的条件) 时, 等到超时返回 false; 未给出超时则立即返回 false.
  • 已附加且已结束配置时立即返回 true, 例如在编辑器中用 "调试" 运行的脚本.
  • 此方法阻塞当前线程, 不宜在 UI 线程中调用; 脚本被停止时立即结束等待.
  • timeout 为负数时抛出 RangeError, 不是数值时抛出 TypeError.
if (debugging.waitForAttach(30000)) {
    console.log('调试器已附加');
} else {
    console.log('30 秒内未附加调试器, 照常运行');
}

[m] breakpoint#

breakpoint()#

6.8.1

  • returns { void }

有调试器附加时, 像 debugger 语句一样在调用处暂停, 暂停原因为 debugger_statement; 未附加时不起作用.

debugging.waitForAttach(30000);
// 已附加时在下一行之前暂停.
debugging.breakpoint();

[m] on#

on(event, listener)#

6.8.1

  • event { 'attach' | 'detach' | 'pause' | 'resume' } - 事件名, 见 事件
  • listener { Function } - 回调, 参数见 事件
  • returns { DebuggingSubscription } - 订阅句柄

监听调试事件.

  • 回调在添加监听器的线程上依次执行. 该线程被调试器暂停时, 回调推迟到它继续运行之后执行.
  • 监听器不会让脚本保持运行; 用句柄的 off(), debugging.off 注销, 或在脚本结束时自动注销.
  • 未知事件名抛出 RangeError, listener 不是函数时抛出 TypeError.
debugging.on('attach', (info) => console.log(`调试器已附加: ${info.frontend}`));
let sub = debugging.on('pause', (e) => console.log(`${e.threadName} 暂停, 原因: ${e.reason}`));
setTimeout(() => sub.off(), 60 * 1000);

[m] once#

once(event, listener)#

6.8.1

  • event { 'attach' | 'detach' | 'pause' | 'resume' } - 事件名
  • listener { Function } - 回调
  • returns { DebuggingSubscription } - 订阅句柄

同 debugging.on, 但回调只执行一次, 之后自动注销.

debugging.once('resume', () => console.log('脚本已继续运行'));

[m] off#

off()#

6.8.1 Overload 1/4

  • returns { void }

移除本脚本的全部调试事件监听器.

off(event)#

6.8.1 Overload 2/4

  • event { 'attach' | 'detach' | 'pause' | 'resume' } - 事件名
  • returns { void }

移除本脚本中该事件的全部监听器.

off(listener)#

6.8.1 Overload 3/4

  • listener { Function } - 监听器
  • returns { void }

移除调用该函数的全部监听器, 不论事件.

off(event, listener)#

6.8.1 Overload 4/4

  • event { 'attach' | 'detach' | 'pause' | 'resume' } - 事件名
  • listener { Function } - 监听器
  • returns { void }

移除该事件中调用该函数的监听器.

let onPause = (e) => console.log(e.reason);
debugging.on('pause', onPause);
debugging.off('pause', onPause);

事件#

事件 触发时机 回调参数
attach 调试器附加到本脚本 info: { frontend }, frontend 为 'editor' (代码编辑器) 或 'remote' (经 3-Probe Debugger 连接的调试器)
detach 调试器离开本脚本, 包括调试服务被关闭 无
pause 本脚本的某个线程暂停 (断点, 单步, 暂停请求, 异常, debugger 语句或 breakpoint) e: { reason, threadName }
resume 本脚本继续运行 (继续或单步请求, UI 线程暂停超时后自动继续, 以及在代码编辑器中调试时 UI 线程停下后立即自动继续) 无

pause 事件的 reason 为下列值之一:

reason 含义
breakpoint 断点 (包括条件断点与命中次数断点)
step 单步执行
pause 调试器的暂停请求
entry 在入口处暂停 (调试器的 stopOnEntry)
exception 异常
debugger_statement debugger 语句或 breakpoint

threadName 为暂停线程的名称, 与调试器中显示的线程名相同.

调试器以 "全部暂停" 模式工作 (默认) 时, 一个线程暂停会让本脚本的其他线程一同暂停, 此时只触发一次 pause 事件.

UI 线程上的暂停:

  • 在代码编辑器中调试时, UI 线程 (如 "ui" 脚本的主体与界面事件回调) 不会停住. 编辑器本身运行在 UI 线程上, 因此 UI 线程停下后立即自动继续 (先触发 pause 事件, 随即触发 resume 事件), 编辑器提示停下的位置, 其他线程不随之暂停, 也无法在该处查看变量.
  • 经 3-Probe Debugger 连接的调试器可以让 UI 线程停下并查看变量, 但暂停默认至多持续 60 秒, 到时自动继续 (触发 resume 事件). 需要调试 UI 线程上的代码时, 使用这种调试器.

类型#

DebuggingSubscription#

on 与 once 返回的订阅句柄.

  • event { string } - 事件名
  • off() - 移除此监听器, 重复调用不起作用
let sub = debugging.on('detach', () => console.log('调试器已分离'));
sub.off();
