项目配置 (project.json)#

project.json 是 AutoJs6 项目的配置文件, 放在项目目录的根目录. 含有 project.json 的目录即为一个项目, 可以存放多个脚本, 模块与资源文件 (参阅 疑难解答 > 图片等资源共同打包及多脚本打包).

本页面不是脚本 API. 本页说明 project.json 的全部键: 类型, 默认值, 取值范围, 别名, 保存时的行为, 以及运行项目和打包应用时各自读取哪些键. 字段信息以 AutoJs6 源码为准, 起始版本只在能够确认时注明.

文件位置与作用#

  • 文件名固定为 project.json, 位于项目目录的根目录. 新建项目时 AutoJs6 自动生成该文件.
  • 在文件管理中进入项目目录后, 顶部的项目工具栏提供运行, 打包与编辑按钮. 编辑按钮打开项目配置页, 打包按钮打开打包页; 两个页面都会把修改写回 project.json (参阅 保存时的行为).
  • 运行项目时读取 main, type, useFeatures, node 与 bun 的部分键; agent 段用于把项目登记为 Agent 可调用的脚本.
  • 打包应用时读取 name, packageName, versionName, versionCode, icon, abis, libs, permissions, signatureScheme, excludeDirs, launchConfig 与 build. launchConfig 只对打包应用起作用. 打包应用运行时还读取 useFeatures (AutoJs6 6.8.1 起, 条件见该条).
  • 运行项目只要求 name 与 main 两项 (AutoJs6 6.8.1 起; 此前通过 VSCode 插件运行缺少 packageName, versionName 或 versionCode 的项目时, 项目会被判定为无效). 读不到有效配置 (例如缺少 name) 时, 普通 JavaScript 项目按默认的 main.js 运行, useFeatures 也不生效.
  • 打包还要求 packageName, versionName 与大于 0 的 versionCode. 缺少 packageName 或 versionName 时, 项目工具栏不显示打包按钮.

完整示例#

下例包含打包常用的键. 只在 AutoJs6 中运行的项目, 写 name 与 main 即可.

{
    "name": "示例项目",
    "packageName": "org.example.demo",
    "versionName": "1.0.0",
    "versionCode": 1,
    "main": "main.js",
    "icon": "res/logo.png",
    "abis": ["arm64-v8a", "armeabi-v7a"],
    "libs": ["OpenCV", "Paddle OCR"],
    "permissions": [
        "android.permission.WAKE_LOCK",
        "android.permission.INTERNET",
        "android.permission.POST_NOTIFICATIONS",
        "android.permission.FOREGROUND_SERVICE",
        "android.permission.FOREGROUND_SERVICE_SPECIAL_USE"
    ],
    "signatureScheme": "V1 + V2",
    "excludeDirs": ["build", "tests"],
    "launchConfig": {
        "logsVisible": true,
        "splashVisible": true,
        "launcherVisible": true,
        "logShortcutVisible": false,
        "settingsShortcutVisible": false,
        "runOnBoot": false,
        "requiresSharedStorage": false,
        "slug": "Powered by AutoJs6"
    },
    "build": {
        "id": "3C1F0A2B-3",
        "number": 3,
        "time": 1762934400000
    }
}

build 段由打包流程生成, 一般不需要手写. node, bun 与 agent 段的示例见各自的章节.

键名与读取规则#

  • 键名不区分大小写, 并忽略字母与数字以外的字符. 例如 versionCode, version_code 与 VERSION-CODE 等价. 此规则适用于顶层, launchConfig 与 build 段 (AutoJs6 6.6.2 起).
  • 许多键有别名, 例如 package 等价于 packageName. 各键的别名列在对应条目中, 来自 AutoJs4 与 AutoX 的别名另见 别名与兼容.
  • 规范键与别名 (或同一键的不同写法) 同时出现时, 读取取 JSON 中最后出现的那个, 不报错; 保存时的处理见 保存时的行为.
  • 布尔类型的键只接受 JSON 布尔值 true / false, 不接受字符串 "true". 值为 null 的键视为未写.
  • node 与 bun 段内的键名区分大小写, 不支持别名与宽松写法.
  • agent 段的键名必须写作小写 agent, 段内的键名区分大小写. 含有 agent 段的 project.json 必须是严格 JSON (不能有注释或末尾多余的逗号), 否则项目不会被登记.
  • project.json 不是合法 JSON 时, AutoJs6 先尝试修复常见的格式错误, 仍然失败时尽可能还原关键信息 (AutoJs6 6.6.1 起), 此时 name 为空则取项目目录名. 这一还原不能代替修正文件, 规则如下:
    • 识别顶层, launchConfig 与 build 段的全部键与别名 (AutoJs6 6.8.1 起; 此前部分写法会被忽略, 按默认值处理, 例如顶层的 version, mainScript 与 ignoredDirs, launchConfig 的 showLogs 与 splashText, build 段的 id, number 与 time).
    • version, package, signature, ignore 与 feature 只在顶层识别; id, number 与 time 只在 build 段 (或其别名 buildInfo) 内识别. 其余键在全文中查找, 写在注释或未知段中的同名键也可能被读取.
    • 不读取 node, bun 与 agent 段 (AutoJs6 6.8.1 起; 此前段中的同名键可能被当作项目配置读取, 例如写在顶层 permissions 之后的 node.permissions 被当作打包应用的权限清单).
    • 同一个键以多种写法出现时取规范键, 不按出现的先后.
    • 键与值可以用双引号或单引号书写 (AutoJs6 6.8.1 起; 此前只识别双引号). 未加引号的键与字符串值不识别.
    • 字符串与列表项中的转义按正常读取的规则还原, 例如 \" 还原为 ", \u4e2d 还原为 中 (AutoJs6 6.8.1 起; 此前保持原样). 正常读取会报错的转义 (例如 \x) 保持原样. 键名中的转义不还原, 用转义写的键名 (例如 "\u006eame") 不识别.
    • 用段名别名写的段 (例如 launch, buildInfo) 保存后保留原写法, 与正常读取相同 (AutoJs6 6.8.1 起; 此前写为规范名, 见 保存时的行为).

保存时的行为#

项目配置页保存, 打包页保存或打包, 打包完成后写回打包信息, 以及新建项目时, AutoJs6 都会重新生成 project.json:

  • 保留用户原来的键名 (AutoJs6 6.7.0 起). 例如原文件用 package, 保存后仍是 package, 不会改成 packageName.
  • 本页没有列出的键 (未知键) 在保存后消失, 例如 AutoJs4 的 scripts. 需要保留的自定义数据请放在其他文件中.
  • 有默认值的键会被写出. 例如没有写 permissions 的项目, 保存后出现默认的 13 项权限; launchConfig 的 8 个键全部写出; agent 段写出 risk, confirm, timeoutMs 等的默认值.
  • 值为空 (未设置) 的键不写出.
  • 在项目配置页或打包页保存时, 同一个键同时以两种写法出现 (例如同时有 packageName 与 package) 会报键名冲突, 需要先删去其中一个 (AutoJs6 6.7.0 起). 打包完成后写回打包信息时不报错, 保留原写法的那个.
  • 打包页保存时, excludeDirs 总会加入 build 目录, permissions 写成完整的权限名.
  • 反向别名 (例如 hideLogs) 在 AutoJs6 6.8.1 之前打包时与写法相反, 每保存一次值也翻转一次, 见 反向别名.

顶层字段#

name#

  • 类型: string
  • 别名: projectName
  • 运行与打包都必须填写.

项目名称. 打包时作为打包应用的应用名称, 输出的 APK 文件名为 <name>_v<versionName>.apk.

versionName#

  • 类型: string
  • 别名: version
  • 打包时必须填写.

版本名称, 例如 "1.0.0", 写入打包应用.

versionCode#

  • 类型: number (整数)
  • 默认值: 1
  • 打包时必须大于 0.

版本号, 写入打包应用. 项目配置页要求它在 32 位整数范围内. 覆盖安装打包应用时, Android 要求新版本号不小于已安装的版本号.

packageName#

  • 类型: string
  • 别名: package
  • 打包时必须填写.

打包应用的包名, 例如 "org.example.demo". 至少两段, 以 . 分隔, 每段以英文字母开头, 只含英文字母, 数字与下划线.

main#

  • 类型: string
  • 默认值: "main.js"
  • 别名: mainName, mainScript, mainScriptName, mainScriptFile, mainScriptFileName, mainFile, mainFileName

主脚本路径, 相对于项目目录. 运行项目时以项目目录为工作目录运行主脚本. 打包时主脚本不能位于项目目录之外.

  • 主脚本不在项目根目录时 (例如 "src/main.js"), 主脚本中以相对路径 require 的模块先在项目根目录下查找, 找不到时再到主脚本所在目录下查找 (AutoJs6 6.8.1 起).
  • type 为 "node" 时, 主脚本的扩展名可以是 js, cjs, mjs, ts, cts 或 mts.
  • 主脚本为 .py 文件时必须同时声明 type 为 "python".
  • 项目登记为 Agent 脚本时, 同时写了多个别名且取值不同的, 执行会被拒绝.

type#

  • 类型: string
  • 别名: projectType

项目类型. 未写时为普通的 AutoJs6 (Rhino 引擎) 项目.

取值 作用
"node" Node.js 项目 (不区分大小写). 运行时使用 Node.js 引擎, 打包时自动带入 Node.js Runtime
"python" Python 项目. 主脚本为 .py 文件时必须声明; Python 项目不能打包
"bun" 打包时带入 Bun 运行时. 运行时是否使用 Bun 引擎由文件名 (如 .bun.js) 或 "bun" 指令决定, 不由此项决定 (参阅 运行时 API)
"quickjs" 打包时被拒绝, 打包应用不支持 QuickJS

assets#

  • 类型: string[]
  • 默认值: []
  • 别名: asset, assetList

目前没有任何功能读取此项, 只在保存时保留. 打包时整个项目目录 (excludeDirs 中的目录除外) 都会进入打包应用, 不需要逐个列出资源文件.

excludeDirs#

  • 类型: string[]
  • 默认值: []
  • 别名: ignoredDirs (AutoJs4, AutoX), ignore, excludedDirs

打包时排除的目录, 相对于项目目录, 末尾的 / 可以省略. 打包页保存时总会加入打包输出目录 build. 使用别名 excludedDirs 时项目配置无法解析的问题已于 AutoJs6 6.7.0 修复 issue #428.

launchConfig#

  • 类型: object
  • 别名: launch

打包应用的启动配置, 见 launchConfig 一节.

build#

  • 类型: object
  • 别名: buildInfo

打包信息, 见 build 一节.

icon#

  • 类型: string
  • 别名: iconPath

图标图片的路径, 相对于项目目录. 打包时用它替换打包应用的启动器图标. 新建项目时为 "res/logo.png".

abis#

  • 类型: string[]
  • 默认值: []
  • 别名: abi, abiList

打包应用包含的 ABI 架构, 可选 arm64-v8a, armeabi-v7a, x86_64, x86 与 armeabi, 打包页也接受常见简写 (如 arm64). 未写或为空时, 打包页预选本机支持的 ABI. 无效的名称在打包页显示为不可用, 打包至少需要一个 ABI (AutoJs6 6.6.0 起).

libs#

  • 类型: string[]
  • 默认值: []
  • 别名: lib, libList

打包应用带入的扩展库, 写名称或简写均可, 不区分大小写 (AutoJs6 6.6.0 起). 可用名称与简写:

名称 简写
OpenCV cv
MLKit OCR mlkit, mlkitocr, mlkit-ocr, mlkit_ocr
Paddle OCR paddle, paddleocr, paddle-ocr, paddle_ocr
Rapid OCR rapid, rapidocr, rapid-ocr, rapid_ocr
OpenCC cc
Pinyin pin

Bun 项目的运行配置, 见 bun 一节 (AutoJs6 6.8.0 起).

permissions#

  • 类型: string[]
  • 默认值: 13 项, 见 权限清单
  • 别名: permission, permissionList

打包应用声明的 Android 权限 (AutoJs6 6.6.3 起) pr #391 issue #362. 写了此项即替换默认清单, 详见 权限清单.

signatureScheme#

  • 类型: string
  • 默认值: "V1 + V2"
  • 别名: signatureSchemes, signature

APK 签名方案. 读取时提取其中的 V1, V2, V3 等 (不区分大小写), 去重并排序后以 " + " 连接, 例如 "v2,v1" 读作 "V1 + V2"; 没有可提取的内容时保留原值.

useFeatures#

  • 类型: string[]
  • 默认值: []
  • 别名: useFeature, useFeatureList, features, feature, featureList

为项目的脚本启用的特性. 目前只有 "continuation", 启用后脚本顶层可以使用 continuation.await 等待 Promise (参阅 续体 (Continuation)).

在 AutoJs6 中运行项目时生效. 打包应用也读取此项 (AutoJs6 6.8.1 起): 这项读取属于打包应用的运行时, 随 APK Builder Template 插件内含的 Runtime Kit 进入打包应用, 需要该 Runtime Kit 来自 AutoJs6 6.8.1 或更高版本. 用更早版本的插件打包时, 即使 AutoJs6 已是 6.8.1, 打包应用也不读取此项: 其中的脚本 continuation.enabled 为 false, 使用 continuation 等待时抛出异常. 已经打包好的应用不会随 AutoJs6 或插件升级而改变, 需要重新打包.

launchConfig#

打包应用的启动配置. 只对打包应用起作用, 在 AutoJs6 中运行项目时不读取. 打包页 "运行配置" 一节可以编辑全部 8 项.

logsVisible 与 runOnBoot 在打包应用首次启动, 覆盖安装或 build.id 变化时复制到打包应用自己的设置中 (分别对应打包应用设置页的 "不显示主界面" 与 "开机时"). 此后以打包应用设置页的开关为准, 直到下一次覆盖安装.

launchConfig.logsVisible#

  • 类型: boolean
  • 默认值: true
  • 别名: showLogs, hideLogs (AutoJs4, AutoX; 反向), displayLogs

启动时是否显示日志页面. 为 true 时打开日志页面并在其中运行主脚本; 为 false 时不显示任何界面 (启动页也不显示), 直接运行主脚本 (参阅 疑难解答 > 打包应用不显示主界面).

launchConfig.splashVisible#

  • 类型: boolean
  • 默认值: true
  • 别名: showSplash, hideSplash (反向), displaySplash (AutoX)

启动时是否显示启动页. logsVisible 为 false 时启动页也不显示.

launchConfig.launcherVisible#

  • 类型: boolean
  • 默认值: true
  • 别名: showLauncher, hideLauncher (AutoX; 反向), displayLauncher

是否在启动器中显示应用图标. 为 false 时, 图标在打包应用首次启动后隐藏, 此后可以通过 runOnBoot 等方式运行脚本. requiresSharedStorage 为 true 且尚未获得共享存储访问时, 图标保持显示.

launchConfig.logShortcutVisible#

  • 类型: boolean
  • 默认值: false
  • 别名: showLogShortcut, hideLogShortcut (反向), displayLogShortcut

长按启动器图标时是否显示 "日志" 快捷方式, 需要 Android 7.1 及以上 (AutoJs6 6.8.0 起) issue #550.

launchConfig.settingsShortcutVisible#

  • 类型: boolean
  • 默认值: false
  • 别名: showSettingsShortcut, hideSettingsShortcut (反向), displaySettingsShortcut

长按启动器图标时是否显示 "设置" 快捷方式, 需要 Android 7.1 及以上 (AutoJs6 6.8.0 起) issue #550.

launchConfig.runOnBoot#

  • 类型: boolean
  • 默认值: false
  • 别名: bootRun, autoRunOnBoot, bootAutoStart, autoStartOnBoot

开机后是否自动运行主脚本 (不显示界面) (AutoJs6 6.7.0 起). 需要 permissions 含有 android.permission.RECEIVE_BOOT_COMPLETED (默认清单已含). AutoJs6 6.8.1 起, 此项为 true 时打包始终保留该权限, 自定义的 permissions 中没有它也一样. 部分系统还需要在系统设置中允许打包应用自启动.

打包应用未声明该权限时 (例如此项为 false 且自定义清单中没有该权限), 打包应用设置页中的 "开机时" 开关不可用, 说明文字为 "不可用: 应用未声明 RECEIVE_BOOT_COMPLETED 权限, 无法开机运行. 请重新打包应用以包含该权限", 见 缺少权限时的表现.

launchConfig.requiresSharedStorage#

  • 类型: boolean
  • 默认值: false

启动前是否要求共享存储访问 (AutoJs6 6.8.0 起). 为 true 时, 未获得访问权限的打包应用在运行脚本前弹出说明对话框: Android 11 及以上前往 "所有文件访问权限" 设置, 以下版本申请读写外部存储权限; 取消则不运行脚本. 开机运行时未获得权限会记录错误并放弃运行.

permissions 中需要含有 android.permission.MANAGE_EXTERNAL_STORAGE (Android 11 及以上) 或读写外部存储权限, 否则对话框不显示前往设置的按钮 (参阅 疑难解答 > 打包应用的共享存储权限).

launchConfig.slug#

  • 类型: string
  • 默认值: "Powered by AutoJs6"
  • 别名: slugText, splashText (AutoX)

启动页上的标语文本, 为空字符串时不显示.

构建 ID, 格式为 <8 位十六进制>-<number>, 由打包时间与打包序号计算.

  • 别名: build_number (AutoJs4, AutoX)

打包序号, 项目每打包一次加 1.

build.time#

  • 别名: build_time (AutoJs4, AutoX)

打包时间, Unix 毫秒.

node#

Node.js 项目 (type 为 "node") 的运行配置 (AutoJs6 6.8.0 起). 段内的键名区分大小写. Node.js 运行时还会读取本段的其他键 (如 featureFlags, bridgeLimits), 这些键由 Node.js 运行时插件定义, 不在本页范围.

{
    "name": "node-demo",
    "type": "node",
    "main": "main.mjs",
    "node": {
        "timeoutMs": 120000,
        "executionMode": "one_shot",
        "entryDirective": "nodejs ui",
        "permissions": ["ui", "toast", "files"]
    }
}

node.backend#

  • 类型: string

保留字段, 目前没有作用.

node.timeoutMs#

  • 类型: number
  • 默认值: 不限

整次执行的期限, 单位为毫秒. 未写, 为 0 或负数时不限时. TypeScript 项目写正数时至少按 30000 计. 项目的启动描述文件写有期限时以启动描述文件为准. 打包应用同样读取此项 (参阅 运行时 API).

node.executionMode#

  • 类型: string
  • 默认值: "one_shot"

执行模式: "one_shot" (单次执行), "interactive_long_running" (交互式常驻) 或 "scheduled" (定时任务). 也接受 oneshot, long_running, longrunning, service, schedule, workmanager, work_manager 等写法, 大小写与 - 不影响识别.

打包应用按此项运行, 与打包时生成的启动描述不一致时报错. 在 AutoJs6 中运行项目时以启动描述为准, 此项只作为诊断信息.

node.entryDirective#

  • 类型: string
  • 默认值: "nodejs"

入口指令, 由 nodejs, ui 与 ui-thread 组成, 例如 "nodejs ui" 或 "nodejs ui ui-thread"; 词之间可用空格, ,, ; 或 | 分隔, 不区分大小写. 含有其他词时报错. 打包应用使用此项, 与打包时生成的启动描述不一致时报错; 在 AutoJs6 中运行时使用主脚本文件自身的指令.

node.permissions#

  • 类型: string[]
  • 默认值: 未声明 (不检查)

项目使用的 Node.js 桥接能力, 例如 "ui", "engines", "files.write". 声明此项 (即使是空数组) 后, 脚本只能使用其中列出的能力; 未声明时不做这一检查. 能力名称不区分大小写, : 视同 .; 父能力包含其子能力 (shell.root, files.write 等少数敏感能力除外, 需要单独声明); 未知的名称只产生警告. 打包时按声明的能力为打包应用补充所需的 Android 权限.

同样的清单也可以写在 node.bridgePermissions, 或 package.json 的 autojs6.permissions 与 autojs6.node.permissions 中 (参阅 运行时 API, ImGui).

bun#

Bun 项目的运行配置 (AutoJs6 6.8.0 起). 段内的键名区分大小写.

{
    "name": "bun-demo",
    "type": "bun",
    "main": "main.bun.js",
    "bun": {
        "timeoutMs": 180000,
        "hostCapabilities": ["ui.layout", "ui.compose"]
    }
}

bun.timeoutMs#

  • 类型: number
  • 默认值: 60000

整次执行的期限, 单位为毫秒, 范围 1-600000, 超出范围时按边界值计. 执行参数 bun.timeoutMillis 优先于此项 (参阅 运行时 API > 打包项目).

bun.hostCapabilities#

  • 类型: string[]
  • 默认值: []

打包应用授予 Bun 脚本的宿主能力, 例如 "ui.layout", "files.control", "agent.control". 打包与运行时都会校验, 未知或重复的名称报错. execution.control 自动授予, 不能写在此处. 声明 notifications.post 或 shell.shizuku 时, 打包会补充对应的 Android 权限.

在 AutoJs6 中运行时不读取此项, 以插件中心的授权开关为准.

agent#

把项目登记为 3-Stove Agent 可以调用的脚本 (AutoJs6 6.8.0 起). 登记后的脚本出现在 ai.agent.catalog 的结果中 (参阅 AgentScriptEntry). 单个脚本文件也可以用文件头的 @agent 注释登记.

{
    "name": "清理下载目录旧安装包",
    "main": "main.js",
    "agent": {
        "id": "clean-download-installers",
        "description": "列出或删除下载目录中超过指定天数的安装包.",
        "parameters": {
            "type": "object",
            "properties": {
                "days": { "type": "integer", "description": "保留最近几天的文件", "minimum": 1, "default": 30 },
                "dryRun": { "type": "boolean", "description": "只列出, 不删除", "default": true }
            },
            "required": []
        },
        "risk": "sensitive",
        "confirm": "before-run",
        "timeoutMs": 60000,
        "examples": ["清理下载目录里一个月前的安装包"],
        "tags": ["files", "cleanup"]
    }
}

agent 段只允许下列 9 个键. 出现其他键或任何一项校验失败时, 项目不会被登记 (目录查询时忽略, 执行时报未登记). 读取登记信息时 project.json 不能超过 256 KiB.

agent.id#

  • 类型: string
  • 默认值: 由项目目录名生成

登记 ID, 只能由小写英文字母与数字组成, 以单个 - 连接, 例如 "clean-download-installers". 未写时由项目目录名转换而来, 无法转换时为 script- 加一段十六进制摘要.

agent.description#

  • 类型: string
  • 必须填写, 不能为空.

用途说明, 供 Agent 选择脚本.

agent.parameters#

  • 类型: object
  • 默认值: 无参数

参数的 JSON Schema 子集:

  • 根对象的 type 必须为 "object", 只允许 type, properties, required 与 additionalProperties 四个键; additionalProperties 只能为 false.
  • required 中的名称不能重复, 且必须在 properties 中定义.
  • 参数名须符合 JavaScript 标识符的写法 (英文字母, 数字, _ 与 $, 不以数字开头).
  • 每个参数只允许 type, description, enum, default, minimum, maximum, minLength, maxLength. type 为 "string", "number", "integer" 或 "boolean"; minimum / maximum 只用于数值, minLength / maxLength 只用于字符串; enum 不能为空且不能有重复值; default 必须符合上述约束.

agent.result#

  • 类型: object

结果说明, 任意 JSON 对象, 供 Agent 理解脚本回传的结果 (参阅 ai.agent.result).

agent.risk#

  • 类型: string
  • 默认值: "normal"

风险等级: "readonly", "normal" 或 "sensitive".

agent.confirm#

  • 类型: string
  • 默认值: "never"

运行前是否需要用户确认: "never" 或 "before-run". risk 为 "sensitive" 时总是 "before-run".

agent.timeoutMs#

  • 类型: number (整数)
  • 默认值: 60000

执行超时, 单位为毫秒, 范围 1-300000.

agent.examples#

  • 类型: string[]
  • 默认值: []

示例目标, 每项为非空字符串, 供检索使用.

agent.tags#

  • 类型: string[]
  • 默认值: []

检索标签, 每项为非空字符串.

权限清单#

permissions 决定打包应用声明哪些 Android 权限.

默认清单#

未写 permissions 时, 打包应用声明以下 13 项. 保存一次 project.json 后, 这 13 项会被写入文件.

android.permission.WAKE_LOCK
android.permission.INTERNET
android.permission.READ_EXTERNAL_STORAGE
android.permission.WRITE_EXTERNAL_STORAGE
android.permission.MANAGE_EXTERNAL_STORAGE
android.permission.POST_NOTIFICATIONS
android.permission.FOREGROUND_SERVICE
android.permission.FOREGROUND_SERVICE_MEDIA_PLAYBACK
android.permission.FOREGROUND_SERVICE_MEDIA_PROJECTION
android.permission.FOREGROUND_SERVICE_SPECIAL_USE
android.permission.RECEIVE_BOOT_COMPLETED
android.permission.REQUEST_IGNORE_BATTERY_OPTIMIZATIONS
android.permission.SYSTEM_ALERT_WINDOW

自定义清单是替换#

写了 permissions 时, 清单整体替换默认清单, 不是在默认清单上追加: 打包应用只保留清单中列出的权限, 默认清单中没有列出的项会被去掉. 清单用于从打包模板已声明的权限中选择保留哪些, 不会为打包应用新增模板中没有的权限.

  • node.permissions 与 bun.hostCapabilities 声明的能力需要的 Android 权限, 打包时另行补充, 不必写进 permissions.
  • 去掉某项权限后, 依赖它的功能在打包应用中无法使用. 例如 runOnBoot 需要 RECEIVE_BOOT_COMPLETED (AutoJs6 6.8.1 起 runOnBoot 为 true 时打包始终保留), Android 14 及以上版本的截图 (images.requestScreenCapture) 需要 FOREGROUND_SERVICE_MEDIA_PROJECTION, requiresSharedStorage 需要共享存储相关权限. 缺少前台服务权限时各功能的表现见 缺少权限时的表现.

始终保留的前台服务权限#

AutoJs6 6.8.1 起, 无论 permissions 如何填写, 打包应用始终保留以下 2 项:

android.permission.FOREGROUND_SERVICE
android.permission.FOREGROUND_SERVICE_SPECIAL_USE

原因: 打包应用的设置页有 "前台服务" 开关, 开启后运行前台服务需要这 2 项权限 (Android 9 及以上需要前一项; Android 14 及以上的前台服务类型为 specialUse, 还需要后一项). 此前, 自定义清单中没有这 2 项时, 在打包应用中开启 "前台服务" 会导致打包应用崩溃 issue #594.

  • 打包页中这 2 项的复选框总是选中且不能取消, 说明文字的最后一行是 "始终保留: 打包后的应用需要此权限运行前台服务". 载入的 project.json 中没有这 2 项时, 复选框同样显示为选中, 在打包页保存后清单中包含它们.
  • 默认清单中的其余 11 项仍可去掉.
  • 使用 AutoJs6 6.8.1 之前的版本打包时, 请在自定义清单中手动加入这 2 项.
  • 已经打包好的应用不会随 AutoJs6 升级而改变. 缺少这 2 项的应用, 需要重新打包才能使用前台服务.

打包应用缺少这 2 项权限时 (例如使用 AutoJs6 6.8.1 之前的版本打包), 开启 "前台服务" 不再崩溃: 开关保持关闭, 并提示一次 "前台服务未启动: 应用未声明 FOREGROUND_SERVICE, FOREGROUND_SERVICE_SPECIAL_USE 权限. 请重新打包应用以包含该权限" (只列出缺少的项). 这项检查属于打包应用的运行时, 随 APK Builder Template 插件内含的 Runtime Kit 进入打包应用, 需要该 Runtime Kit 来自 AutoJs6 6.8.1 或更高版本; 更早的 Runtime Kit 打包出的应用缺少权限时仍会崩溃.

两部分修复分别到达打包应用:

修复 所在位置 生效条件
打包时保留这 2 项 AutoJs6 (宿主) 使用 AutoJs6 6.8.1 或更高版本打包, 与 APK Builder Template 插件的版本无关
缺少权限时不开启前台服务 打包应用的运行时 (Runtime Kit) APK Builder Template 插件的 Runtime Kit 来自 AutoJs6 6.8.1 或更高版本

缺少权限时的表现#

以下功能运行时要启动前台服务: Android 9 及以上需要 FOREGROUND_SERVICE, Android 14 及以上还需要表中对应类型的权限. 打包应用未声明这些权限时, AutoJs6 6.8.1 起不再启动前台服务, 而是报错并写明缺少的权限, 打包应用不会崩溃.

功能 Android 14 及以上还需要 缺少权限时
截图 (images.requestScreenCapture) FOREGROUND_SERVICE_MEDIA_PROJECTION 不弹出截图授权, images.requestScreenCapture 抛出异常
网页的后台录音与后台录像 (后台网页录音) 按所用的设备: FOREGROUND_SERVICE_CAMERA, FOREGROUND_SERVICE_MICROPHONE 网页的相机 / 麦克风请求被拒绝, 并经 webCallbackError 报告原因; view.startBackgroundRecording 返回的 Promise 被拒绝
recorder 模块的录音 (Node.js 录屏与音频) FOREGROUND_SERVICE_MICROPHONE 录音无法开始, 返回错误

错误信息为英文, 写出完整的权限名, 例如:

Screen capture foreground service not started: the manifest of this app does not request android.permission.FOREGROUND_SERVICE_MEDIA_PROJECTION. For a packaged app, add it to "permissions" in project.json and build the app again

把错误信息中的权限加入 permissions 后重新打包即可.

  • FOREGROUND_SERVICE_MEDIA_PROJECTION 在默认清单中, 但不属于 始终保留的前台服务权限: 自定义清单中没有它时, 打包应用在 Android 14 及以上版本不能截图. 此前这种情况下仍会弹出截图授权, 同意后系统拒绝启动截图所需的前台服务, images.requestScreenCapture 抛出系统的 SecurityException issue #594.
  • 相机与麦克风的前台服务权限不在默认清单中. 清单含 CAMERA / RECORD_AUDIO 时, APK Builder Template 插件同时保留对应的 FOREGROUND_SERVICE_CAMERA / FOREGROUND_SERVICE_MICROPHONE (见 打包权限与平台边界), 一般不会遇到表中后两行的情况.
  • 打包应用未声明 RECEIVE_BOOT_COMPLETED 时, 设置页中的 "开机时" 开关不可用并说明原因, 见 launchConfig.runOnBoot.
  • 上述检查属于打包应用的运行时, 随 APK Builder Template 插件内含的 Runtime Kit 进入打包应用, 需要该 Runtime Kit 来自 AutoJs6 6.8.1 或更高版本, 已经打包好的应用需要重新打包. runOnBoot 为 true 时保留 RECEIVE_BOOT_COMPLETED 是打包时的处理, 在 AutoJs6 (宿主) 中, 与 APK Builder Template 插件的版本无关.

打包页的权限列表#

打包页的 "需要的权限" 列出 72 项常用权限, 载入 project.json 时按以下规则匹配清单中的项:

  • 不区分大小写.
  • android.permission.* 可以只写最后一段, 且 - 与 _ 等价, 例如 "wake-lock" 匹配 android.permission.WAKE_LOCK.
  • "shizuku" 匹配 moe.shizuku.manager.permission.API_V23, "termux" 匹配 com.termux.permission.RUN_COMMAND.

在打包页保存后, 清单只含列表中勾选的项, 并写成完整的权限名. 列表之外的权限会被去掉, 需要它们时直接编辑 project.json 并且不在打包页中保存. 简写只在打包页中识别, 建议直接写完整的权限名.

别名与兼容#

反向别名#

以下 5 个别名与规范键含义相反, 读取时把值取反. 例如 "hideLogs": true 等同于 "logsVisible": false.

反向别名 规范键
hideLogs logsVisible
hideSplash splashVisible
hideLauncher launcherVisible
hideLogShortcut logShortcutVisible
hideSettingsShortcut settingsShortcutVisible

保存 project.json 时保留原来的键名 (见 保存时的行为). AutoJs6 6.8.1 起, 写回反向别名时同样把值取反, 保存与打包前后含义不变. 这项修复在 AutoJs6 (宿主) 中, 与 APK Builder Template 插件的版本无关.

AutoJs6 6.8.1 之前的版本写回反向别名时没有取反 issue #596:

  • 打包出的应用与写法相反, 第一次打包就是如此. 例如写了 "hideLogs": true 的项目, 打包应用仍显示日志页面; 写了 "hideLogs": false 的项目, 打包应用反而不显示日志页面.
  • 每保存一次 (项目配置页保存, 打包页保存或打包, 打包完成后写回打包信息), project.json 中的值就翻转一次. 例如 "hideLogs": true 保存后变成 "hideLogs": false.

规避方式: 改用规范键 (如 "logsVisible": false), 并核对一次当前的值. 已被旧版本翻转过的值无法判断哪一次才是本意, AutoJs6 6.8.1 不会自动更正, 请按需要的效果重新填写. 用旧版本打包的应用, 改好后用 AutoJs6 6.8.1 重新打包并覆盖安装.

来自 AutoJs4 与 AutoX 的键#

以下别名来自 AutoJs4 或 AutoX 的 project.json, AutoJs6 可以直接读取, 保存时保留原键名:

键 来源 对应的规范键
ignoredDirs AutoJs4, AutoX excludeDirs
hideLogs (反向) AutoJs4, AutoX launchConfig.logsVisible
displaySplash AutoX launchConfig.splashVisible
hideLauncher (反向) AutoX launchConfig.launcherVisible
splashText AutoX launchConfig.slug
build_id AutoJs4, AutoX build.id
build_number AutoJs4, AutoX build.number
build_time AutoJs4, AutoX build.time

AutoJs4 的 scripts (为单个脚本设置的配置) 不受支持, 保存后会被删除.

常见问题#

保存后 project.json 的内容变了#

保存时 AutoJs6 重新生成文件: 有默认值的键被写出, 未知键被删除, 打包页还会加入 build 排除目录与完整的权限名 (见 保存时的行为). 需要保留的自定义数据请放在其他文件中.

hideLogs 等配置每次保存后都会反过来#

这是 AutoJs6 6.8.1 之前的问题: 写回反向别名时没有取反, 打包出的应用也与写法相反, 见 反向别名. 改用 logsVisible 等规范键可以避免; 已被翻转的值不会自动改回, 需要核对一次.

打包应用开启 "前台服务" 后崩溃#

自定义的 permissions 中缺少前台服务权限. AutoJs6 6.8.1 起打包时始终保留这 2 项, 用它重新打包即可; 使用此前的版本时, 在清单中加入 android.permission.FOREGROUND_SERVICE 与 android.permission.FOREGROUND_SERVICE_SPECIAL_USE 后重新打包. 打包应用的运行时来自 AutoJs6 6.8.1 或更高版本时, 缺少权限不再崩溃, 开关保持关闭并提示原因 (见 始终保留的前台服务权限).

打包应用同意截图授权后仍无法截图#

Android 14 及以上版本中, 自定义的 permissions 缺少 android.permission.FOREGROUND_SERVICE_MEDIA_PROJECTION 时, 打包应用调用 images.requestScreenCapture 仍会弹出截图授权, 同意后系统拒绝启动截图所需的前台服务, images.requestScreenCapture 抛出 SecurityException (信息含 "Starting FGS with type mediaProjection"). 在清单中加入该权限后重新打包即可. 打包应用的运行时来自 AutoJs6 6.8.1 或更高版本时, 缺少该权限时不再弹出截图授权, images.requestScreenCapture 直接抛出写明所缺权限的异常 (见 缺少权限时的表现).

写进 permissions 的权限在打包页保存后不见了#

打包页只保留其列表中勾选的权限, 见 打包页的权限列表.

修改 launchConfig 后, 已安装的打包应用没有变化#

logsVisible 与 runOnBoot 只在打包应用首次启动, 覆盖安装或 build.id 变化时复制到打包应用的设置, 之后以打包应用设置页的开关为准. 重新打包并覆盖安装, 或在打包应用的设置页中修改.

保存时提示键名冲突#

同一个键以两种写法同时出现, 例如同时有 packageName 与 package, 或同时有 logsVisible 与 hideLogs. 删去其中一个后再保存.

agent 段写了, 但项目没有出现在 Agent 脚本目录中#

逐项检查: 键名是否为小写 agent; 文件是否为严格 JSON (没有注释和多余的逗号); agent 段是否只含 9 个允许的键; description 是否非空; id, risk, confirm, timeoutMs 与 parameters 是否符合 agent 一节的约束.

打包应用中 continuation 不可用#

AutoJs6 6.8.1 起打包应用也读取 useFeatures. 仍不可用时, 检查打包时使用的 APK Builder Template 插件: 它内含的 Runtime Kit 需要来自 AutoJs6 6.8.1 或更高版本, 用更早版本的插件打包出的应用不读取 useFeatures (continuation.enabled 为 false). 升级插件后重新打包即可, 已经安装的打包应用不会自动改变. 不便重新打包时, 脚本可以改用 async 函数与 await (参阅 async/await 与 continuation).

assets 中列出的文件没有被打包#

assets 不起作用, 打包时整个项目目录都会进入打包应用. 文件没有出现在打包应用中时, 检查它是否位于 excludeDirs 列出的目录中.
