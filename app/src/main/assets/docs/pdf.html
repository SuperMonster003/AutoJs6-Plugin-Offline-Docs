PDF 文档 (PDF)#

运行时支持 Rhino Node.js 主线程 Node.js Worker Bun
入口 pdf autojs6:pdf, $autojs.pdf autojs6:pdf, $autojs.pdf host.pdf
状态 已支持 45 项 已支持 45 项 已支持 45 项 需授权 45 项
授权 - - - pdf.control 45 项

各 API 在同一运行时中的入口, 状态与授权一致, 没有差异项.

Node.js 与 Bun 的导入方式, 异步返回值与授权检查见 运行时 API.

pdf 模块用于在脚本中读取 PDF 文档的信息, 目录 (书签), 文本与图片, 搜索关键词, 把页面渲染为图像或图片文件, 合并, 拆分, 提取, 删除, 重排与旋转页面, 从图片, 文本或 HTML 生成 PDF, 加密与解密, 以及打开插件的查看器并接收翻页事件. 没有文本层的扫描页可借助已安装的 OCR 插件识别文字.

从 AutoJs6 6.8.1 起, 本模块由外置 3-Paper PDF 插件 (AutoJs6-Plugin-Three-Paper-PDF) 1.0.0 及以上版本提供. 调用前需在插件中心安装并启用与当前 AutoJs6 兼容的插件. 插件缺失, 被禁用或版本不兼容时, 方法抛出 (或以 Promise 拒绝) code 为 PLUGIN_UNAVAILABLE, PLUGIN_DISABLED 或 PLUGIN_INCOMPATIBLE 的 PdfError. pdf.isAvailable 可预先探测. 由 AutoJs6 打包的应用同样可以使用本模块, 前提是运行它的设备已安装 3-Paper PDF 1.0.0 及以上版本, 应用由 AutoJs6 6.8.1 及以上版本打包, 且带有 org.autojs.plugin.pdf.permission.RUNTIME 权限 (由打包流程自动加入, 不需要修改 project.json). 打包应用经插件单独的服务与查看器入口调用, 打开的文档与查看器会话只允许创建它们的应用调用.

本模块在 Rhino 中注册为全局名称 pdf, 并提供 $pdf 别名, 二者指向同一对象. 本页的签名与同步返回值描述 Rhino. Node.js, Bun 与 Node.js Worker 提供显式导入的异步接口, 参阅 Runtime APIs 的 pdf.

let path = '/sdcard/Documents/report.pdf';
let info = pdf.info(path);
console.log(info.pageCount, info.title);
let texts = pdf.text(path, { pages: '1-2' });
texts.forEach((text, i) => console.log('第 ' + texts.pages[i] + ' 页:', text.slice(0, 80)));
console.log(pdf.extract(path, '1-3').path); // /sdcard/Documents/3-Paper PDF/report-extract-20261113-153000.pdf

准备工作#

  1. 在插件中心安装并启用 3-Paper PDF.
  2. 授予 AutoJs6 存储权限. 输入与输出文件都由 AutoJs6 打开, 再以文件描述符交给插件, 插件不会得到任何路径, 也不需要自己的存储权限. AutoJs6 无法读写某个文件时调用失败于 IO_ERROR.
  3. 需要识别扫描页时, 另装一个 OCR 插件 (ML Kit OCR, Paddle OCR 或 Rapid OCR), 见 文字识别 (OCR).

路径与输出#

输入文件以路径指定, 相对路径按脚本工作目录解析 (与 files.path 相同), 也可使用绝对路径. 不接受 content://, file:// 等 URI (INVALID_ARGUMENT, 消息为 "must be a file path, URIs are not accepted"). 路径为空白, 是目录或不存在时, 调用分别失败于 INVALID_ARGUMENT, INVALID_ARGUMENT 与 FILE_NOT_FOUND.

写出文件的方法有一个可选的输出参数 (output 或 outputDir), 按值的类型判断是否给出:

  • 字符串: 输出路径, 相对路径同样按脚本工作目录解析.
  • null 或 undefined: 使用默认输出, 但占用这个参数位置, 后面可以继续传选项.
  • 其他值 (数字, 数组, 对象): 视为省略输出, 该值属于下一个参数. 例如 pdf.rotate(path, 90) 与 pdf.rotate(path, null, 90) 相同.

默认输出位于 /sdcard/Documents/3-Paper PDF/ (外部存储的 Documents 目录), 文件名为 <源名>-<操作>-<yyyyMMdd-HHmmss>.<扩展名>, 重名时依次追加 -1, -2 等; 输出目录 (split, extractImages) 的名称不带扩展名. 源名为输入文件名去掉扩展名: merge 与 fromImages 取第一个输入, fromText 为 text, 以 HTML 字符串调用的 fromHtml 为 html, 名称为空时为 pdf. 操作名为方法名, 只有 renderToFile 为 render-p<页码>, extractImages 为 images, PdfDocument#save 为 save.

输出的写入方式:

  • 显式给出的输出文件已存在时被覆盖, 输出也可以是输入文件本身.
  • 结果先写入同目录的隐藏文件 .<文件名>.<随机串>.part, 完成后改名为目标文件; 调用失败或被取消时删除该文件, 目标路径下不会留下不完整的文件.
  • 输出路径是已存在的目录时失败于 INVALID_ARGUMENT. 父目录不存在时自动创建, 无法创建时失败于 IO_ERROR.
  • 输出目录不存在时自动创建, 已存在但是文件时失败于 INVALID_ARGUMENT.

split 与 extractImages 的 namePattern 选项决定目录中各文件的名称:

  • 占位符 {name} 为源名, {index} 为序号 (从 1 计), {page} 为页码. split 的部分不对应单一页码, 其中的 {page} 展开为空.
  • 不能为空白, 不能含 /, \ 或 NUL. 展开后的不安全字符 (\ / : * ? " < > | 与控制字符) 替换为 _, 文件名截断到 120 个字符, 并自动补上扩展名.
  • 展开后有重名 (不区分大小写) 时失败于 INVALID_ARGUMENT, 消息提示加入 {index} 或 {page}.

页码与页码范围#

页码从 1 计. 接受页码范围的参数与 pages 选项可以是:

  • 字符串: 以逗号分隔的 N, N-M (N <= M) 或 N- (到最后一页), 例如 '1-3,5,8-', 空白被忽略.
  • 数字: 单独一页.
  • 数组: 每项为页码或上述字符串, 例如 [1, 3, '5-7'].

范围不能为空, 结束页不能小于起始页 (INVALID_ARGUMENT); 超出文档页数时失败于 PAGE_OUT_OF_RANGE. 选中的页按升序且不重复处理. 省略 pages 表示全部页.

同步, 异步与进度#

每个方法都有同步形态 x(...) 与异步形态 xAsync(...), 二者参数与结果完全一致.

  • 同步形态阻塞当前脚本线程直至插件返回结果或调用失败. 同步形态不能在 UI 线程调用 (失败于 INVALID_ARGUMENT), UI 模式中请使用 Async 形态. 停止脚本会取消尚未完成的调用.
  • 异步形态立即返回 Promise, 回调在脚本线程执行. 参数错误同样以 Promise 拒绝体现, 不同步抛出. 返回的 Promise 带有不可枚举, 只读的 cancel() 方法: 调用仍在进行时返回 true 并取消任务, 之后 Promise 以 CANCELLED 拒绝; 调用已结束时返回 false.
  • 传给插件的参数会像 JSON.stringify 一样序列化, 函数被忽略 (onProgress 除外), 无法表示为 JSON 的值失败于 INVALID_ARGUMENT. options 必须是对象, 未知的选项键以 INVALID_ARGUMENT 拒绝 (消息形如 "unknown option 'options.key'"). 参数个数超过签名时同样失败于 INVALID_ARGUMENT (消息形如 "pdf.info takes at most 2 arguments, got 3"), 末尾的 null 与 undefined 不计入.

报告进度的调用 (写出 PDF 的方法, extractImages, PdfDocument#save 以及 text 的 OCR 分支) 接受选项 onProgress, 它收到 PdfProgress 对象. 同步形态在调用线程等待结果的间隙执行它, 异步形态在脚本线程执行它. onProgress 抛出错误时任务被取消, 调用以该错误结束, 不保留输出.

let promise = pdf.mergeAsync(['./a.pdf', './b.pdf'], './ab.pdf', {
    onProgress: p => console.log(p.stage, p.percent + '%'),
});
promise.then(r => console.log(r.path, r.pageCount)).catch(e => console.error(e.toString()));
setTimeout(() => promise.cancel(), 5000);

加密文档与密码#

打开加密文档时用选项 password 传入用户密码或所有者密码 (至多 127 个字符). 未给密码时失败于 PASSWORD_REQUIRED, 密码错误时失败于 WRONG_PASSWORD. 读取 (信息, 文本, 搜索, 渲染, 图片) 用用户密码即可, 不受文档权限位的限制.

页面操作 (merge, split, extract, delete, reorder, rotate, PdfDocument#save) 写出的文档不加密. 加密的源文档须以所有者密码打开: 只给用户密码时这些操作失败于 PERMISSION_DENIED. 需要保护结果时再对它调用 encrypt.

文字识别 (OCR)#

扫描件的页面只有图像, 没有文本层, text 对这类页面返回空字符串. 识别它们的文字有两种做法, 都需要已安装的 OCR 插件 (ML Kit OCR, Paddle OCR 或 Rapid OCR):

  1. 一步完成: pdf.text 或 PdfDocument#text 带选项 ocr. ocr: true 只识别范围内文本层缺失或为空白的页, ocr: 'always' 识别范围内的每一页. 每页以 ocrDpi (默认 300, 1 至 2400) 渲染后交给 OCR 引擎, 各行以 \n 连接, 结果按页序合并, 其 sources 对识别的页标为 'ocr', 其他页为 'text'. 进度的 stage 为 'ocr', 每识别一页推进一次.
  2. 手动: pdf.render 把页面渲染为 ImageWrapper (OCR 建议 300 dpi), 交给 ocr.recognizeText 取文字, 或交给 ocr.detect 取每段文字及其位置, 用完调用图像的 recycle() 释放. 适合需要文字位置, 只识别部分区域或先做预处理的场合.

ocrOptions 选择 OCR 引擎, 只能与 ocr: true 或 'always' 同时使用 (否则失败于 INVALID_ARGUMENT, 消息为 "'options.ocrOptions' needs ocr: true or 'always'"):

  • mode { 'auto' | 'mlkit' | 'paddle' | 'rapid' } - 引擎种类, 'auto' 任选可用的引擎. 省略时沿用 ocr.mode (其值为 'auto' 时任选).
  • engineId / engine / variant / profile { string } - 精确指定引擎实例, 含义与 OcrOptions 中的同名键相同.

只有存在需要识别的页时才查找 OCR 引擎, 文本层完整的文档不需要 OCR 插件. 找不到可用引擎时调用失败于 OCR_UNAVAILABLE, 消息说明原因.

let path = '/sdcard/Documents/scanned.pdf';

/* 一步完成: 只识别没有文本层的页. */
