闹钟 (Alarms)#

运行时支持 Rhino Node.js 主线程 Node.js Worker Bun
入口 alarms, alarms.ringtones, alarms.system - - -

各 API 在同一运行时中的入口, 状态与授权一致, 没有差异项.

Node.js 与 Bun 的导入方式, 异步返回值与授权检查见 运行时 API.

alarms 模块用于在脚本中管理 3-Chime Alarm 插件的闹钟: 新建, 查询, 修改与删除闹钟, 推算重复规则的响铃时刻, 处理正在响的闹钟, 监听响铃等事件, 以及把脚本登记到闹钟事件上, 由事件启动脚本. 子模块 alarms.system 不需要插件, 它通过 Android 的 AlarmClock Intent 使用系统的时钟应用.

脚本可以读写用户在插件界面里建的闹钟, 用户也能在插件界面看到并修改脚本建的闹钟. 插件界面为每个闹钟标出创建来源与最后修改来源 (用户, 脚本, 插件工具或系统时钟 Intent), 对应 Alarm 的 source 与 updatedBy.

从 AutoJs6 6.8.1 起, 本模块由外置 3-Chime Alarm 插件 (AutoJs6-Plugin-Three-Chime-Alarm) 1.0.0 及以上版本提供. 闹钟的存储, 排程与响铃都在插件中完成: AutoJs6 没有运行, 被强行停止甚至被卸载时, 闹钟照常响铃. 调用前需在插件中心安装并启用与当前 AutoJs6 兼容的插件. 插件缺失时方法抛出 code 为 PLUGIN_UNAVAILABLE 的 AlarmError; 插件被禁用或未授权时为 PLUGIN_DISABLED; 插件版本或契约不兼容, 或插件未声明调用所需的功能时为 PLUGIN_INCOMPATIBLE. alarms.isAvailable 可预先探测. 插件本身可以作为独立的闹钟应用使用: 在不满足版本要求的 AutoJs6 上, 插件中心不能启用它, 本模块与它的 插件工具 不可用, 但插件界面与系统时钟 Intent 的接收照常可用.

本模块在 Rhino 中注册为全局名称 alarms, 并提供 $alarms 别名, 二者指向同一对象. Node.js, Bun 与 Node.js Worker 不提供本模块; 这些运行时可以用 engines.execScript 运行一个调用 alarms 的 Rhino 脚本.

约定:

  • 方法都是同步的: 每次调用经 Binder 到达插件并等待应答. 一般调用至多等待 15 秒, 导入铃声文件至多等待 60 秒, 超时抛出 TIMEOUT.
  • 选项先由 AutoJs6 检查, 再由插件检查一次, 以插件的结论为准. 未知的选项键按名称以 INVALID_OPTIONS 拒绝, 不会被静默忽略; 类型或取值范围错误同样为 INVALID_OPTIONS; 超出长度, 条数或大小上限为 LIMIT_EXCEEDED; 重复规则不合法为 INVALID_RULE. 值为 undefined 的属性视为省略.
  • 星期编号 0 至 6 依次为星期日到星期六, 与 Date#getDay 一致.
  • 相对路径 (本地铃声文件, 登记的脚本) 按当前脚本的工作目录解析.
  • 时刻 (createdAt, nextTrigger, scheduledAt 等) 均为 Unix 毫秒时间戳; 接受时刻的参数也接受 Date 对象.
let a = alarms.add({ time: '07:30', repeat: [1, 2, 3, 4, 5], label: '起床' });
console.log(a.id, a.repeat, a.repeatText, new Date(a.nextTrigger));

准备工作#

  1. 在插件中心安装并启用 3-Chime Alarm (安装向导的 "工具" 分类).
  2. 打开插件 (或调用 alarms.openPlugin('permissions')), 在权限页逐项处理:
    • 精确闹钟: Android 12 与 12L 需要用户在系统设置中允许 "闹钟和提醒", Android 13 起安装即授予. 缺少时, 会留下启用闹钟的 add, update 与 setEnabled 抛出 PERMISSION_REQUIRED.
    • 通知 (Android 13 起需要授权): 缺少时闹钟照常发声与振动, 但没有通知与响铃界面, 只能由脚本, 自动停止或删除闹钟结束这一轮响铃.
    • 全屏通知 (Android 14 起可能未授予): 缺少时以悬浮通知响铃, 点按通知打开响铃界面.
    • 电池优化, 后台限制与厂商自启动: 按页面说明设置, 避免系统清理插件后闹钟无法按时响铃. ColorOS 另有 "自动启动列表" 一行, 见 ColorOS 的自动启动.
  3. 需要用 alarms.bind 登记脚本时, AutoJs6 本身也不应被系统禁止自启动.

alarms.capabilities 的 permissions 给出插件当前持有的精确闹钟, 通知与全屏通知权限. 缺少通知或全屏通知权限不会让任何调用失败.

响铃的可靠性#

  • 闹钟以精确闹钟排程. 设备重启, 系统时间或时区改变, 插件升级之后, 插件自动重新排程; 设备开机后首次解锁之前也会响铃.
  • 时间按 "墙上时间 + 时区" 保存, 默认跟随设备时区, 也可以用 timeZone 固定时区. 夏令时跳过的时刻顺延到跳变后的第一刻, 重复出现的时刻只响第一次.
  • 关机或系统推迟导致错过触发时刻时, 5 分钟内补响; 超过 5 分钟不响, 发出 miss 事件并留一条通知. 开机后发现的错过原因为 off, 其他为 late; 关机多天时每个闹钟只报一次.
  • 多个闹钟同时到期时排队: 同一时间只有一个闹钟发声, 前一个贪睡, 关闭或自动停止后, 下一个开始发声并发出 ring 事件.
  • 插件进程在响铃中被系统回收时, 进程再次启动后继续这一轮响铃, 再发一次 ring 事件, occurrence 不变.
  • 插件被 "强行停止" 时, 系统会清除它的全部闹钟排程, 停止期间到点不响. 从启动器打开一次插件即恢复排程; 恢复时尚在 5 分钟窗口内的闹钟会补响.
  • 小米 (MIUI, HyperOS) 可能在开机后多次结束插件进程, 实测到点时系统仍会拉起插件并按时响铃.

ColorOS 的自动启动#

ColorOS (OPPO, 一加, realme) 有两套互相独立的开关:

  • 应用详情页中的 "允许自启动", "关联启动" 与 "后台活动".
  • 设置 > 应用 > "自动启动" 列表.

只打开前者不够. "自动启动" 列表中 3-Chime Alarm 关闭时, 插件进程一旦被清理 (例如在最近任务中被划掉), 到点的闹钟广播会被系统拦下, 闹钟不响. 两处都要为 3-Chime Alarm 打开; 使用 alarms.bind 登记脚本时, 两处也要为 AutoJs6 打开, 否则 AutoJs6 被清理后无法被闹钟事件拉起. 插件权限页在 ColorOS 上有 "自动启动列表" 一行: 该列表页需要系统权限, 应用不能直接打开它, 因此点按后打开系统设置, 再进入 应用 > 自动启动. 实测设备为一加 OPD2413 (ColorOS 15.0.1.801).

此外:

  • 在最近任务中锁定插件可避免被误划掉, 但不能代替 "自动启动" 列表.
  • 不方便打开 "自动启动" 时, 可以在插件设置页打开 "保持后台运行" (默认关闭): 有启用的闹钟时, 插件保持一个最低重要性通知的前台服务, 进程不会被后台清理, 闹钟照常响铃, 耗电略有增加. 没有启用的闹钟时该服务自动停止.

事件#

事件 时机 专有字段
ring 开始发声, 包括贪睡后再响, 以及排队后开始发声 snoozeCount
snooze 贪睡 by, minutes, snoozeCount
dismiss 关闭; 正在响, 排队或贪睡中的闹钟被删除或禁用时也以 dismiss 结束这一轮 by, challenge
silence 无人处理, 响满 autoSilenceMinutes 后自动停止 ringMillis
miss 错过触发时刻且超过 5 分钟的补响窗口 reason
skip 这一次不响 reason, detail
change 闹钟被新建, 修改或删除 (任何来源) action, source
beforeRing 响铃之前 (需要插件的 beforeRing 功能, 插件 1.0.0 不提供) deadline

各字段见 AlarmEvent. 补充说明:

  • dismiss 的 by 为 'user' (插件界面, 通知或系统时钟 Intent), 'script', 'tool' (插件工具) 或 'challenge' (关闭挑战).
  • skip 的 reason 在插件 1.0.0 中只有 'skipNext' (见 alarms.skipNext); 'holiday' 与 'script' 属于插件将来的节假日与 beforeRing 功能.
  • change 由任何来源的新建, 修改与删除触发 (脚本, 插件界面, 插件工具, 系统时钟 Intent). 没有实际改变的调用不发 change; 一次性闹钟响过后被插件自动禁用时也不发. action 为 'remove' 的事件带闹钟被删除前的 label.
  • 插件 1.0.0 不提供 beforeRing: 监听或登记该事件抛出 PLUGIN_INCOMPATIBLE.

occurrence 标识 "一轮响铃", 是插件生成的不透明字符串:

  • 同一次计划响铃的 skip, miss 与第一次 ring 共用一个值.
  • 贪睡后再响是新的一轮, 有新的值, 其 scheduledAt 为贪睡结束的时刻; snooze, dismiss 与 silence 带它们所结束那一轮的值.
  • 每个 change 事件有自己的值.

脚本联动#

有两种方式让脚本对闹钟事件作出反应, 两者互不依赖, 既登记又在监听的脚本两种都会收到:

  • 实时监听: alarms.on 与 alarms.once. 监听期间脚本保持运行, 事件在脚本线程上回调, 适合常驻脚本.
  • 登记脚本: alarms.bind 把脚本文件登记到某个闹钟的事件上. 事件发生时 AutoJs6 启动该脚本, 即使它当时没有运行; AutoJs6 进程被系统回收后也会被插件的广播拉起. 绑定保存在 AutoJs6 中, 插件只知道哪些闹钟的哪些事件有绑定, 不知道脚本路径; 插件界面标出有绑定的闹钟, 用户可以在那里解除绑定.

被启动的脚本中, engines.myEngine().execArgv.alarm 是该事件的普通 JSON 对象 (形态见 AlarmEvent), alarms.currentEvent 返回同一个对象.

/* after-wake.js, 登记在闹钟的 dismiss 事件上. */
let e = alarms.currentEvent();
if (e !== null && e.type === 'dismiss') {
    toastLog(`${e.label} 已关闭 (${e.by})`);
}

登记的脚本按以下规则启动:

  • 每个 (occurrence, 事件, 脚本) 只启动一次: 插件因进程重启重复发送的事件不会再次启动脚本; 贪睡后再响是新的一轮, 登记在 ring 上的脚本会再次启动. AutoJs6 只记住本进程最近 512 次启动.
  • 脚本文件不存在时跳过并记一条日志.
  • 设备开机后首次解锁之前, AutoJs6 不能运行脚本: 闹钟照常响铃, 登记的脚本不启动, 解锁后也不补启动.
  • AutoJs6 被 "强行停止" 后, 系统不向它投递广播: 闹钟照常响铃, 登记的脚本不启动, 直到 AutoJs6 再次被打开. 进程只是被系统回收 (没有被强行停止) 时, 广播会拉起 AutoJs6 并启动脚本.
  • 插件不重试也不排队, 以上情形中错过的启动不会补上. 原因记在插件日志中 (adb logcat -s ChimeTrigger): locked 表示设备尚未解锁, unavailable 表示 AutoJs6 未安装, 被强行停止, 被禁用或版本过低.

删除闹钟时:

  • 无论由谁删除 (包括本脚本调用 alarms.remove), 登记在该闹钟 change 事件上的脚本都会以 action 为 'remove' 的事件启动一次, 然后 AutoJs6 删除该闹钟的全部绑定.
  • alarms.remove 返回 true 后, alarms.bindings 不再列出该闹钟的绑定. 插件的删除广播 10 秒内没有到达时 (例如插件进程被结束), AutoJs6 自行删除这些绑定, 此时 change 脚本不会启动.

[p+] system#

alarms.system 通过 Android AlarmClock Intent 使用系统的时钟应用, 不需要 3-Chime Alarm 插件. 闹钟由时钟应用保存, 不需要时在时钟应用中删除.

  • 方法返回 true 只表示有应用接收了 Intent, 不保证时钟应用已建好闹钟或已执行操作.
  • 不写 package 时把 Intent 交给系统解析: 有默认时钟应用时直接交给它, 有多个候选时由用户在选择器中选择. 写 package 时交给该应用中处理此动作的界面, 该应用不处理时抛出 NO_HANDLER.
  • 没有任何应用能处理时抛出 NO_HANDLER; 设备的 Android 版本低于该动作所需时抛出 UNSUPPORTED; 选项错误为 INVALID_OPTIONS.
  • 3-Chime Alarm 也接收这些 Intent. 用户把它设为默认时钟应用, 或在选择器中选了它时, alarms.system 建的闹钟进入 3-Chime Alarm, 来源记为 'intent'; 也可以写 package: 'io.github.supermonster003.autojs6.plugin.three.chime.alarm' 直接指定它. 插件 1.0.0 处理 setAlarm, showAlarms, dismissAlarm 与 snoozeAlarm, 不处理计时器的三个动作.

重复规则#

repeat 接受三种写法, 都转为一条不带 RRULE: 前缀的规范 RRULE (RFC 5545) 保存, Alarm 的 repeat 总是回读这一形式, repeatText 给出插件界面语言的可读描述:

  • RRULE 字符串, 如 'FREQ=MONTHLY;BYDAY=-1FR', 可带 RRULE: 前缀, 大小写不限, 只能有一行.
  • 星期编号数组, 如 [1, 2, 3, 4, 5], 即 FREQ=WEEKLY 加 BYDAY. 空数组抛出 INVALID_RULE.
  • 结构化规则 RepeatRule.

规范形式的各部分依次为 FREQ, INTERVAL (为 1 时省略), COUNT, UNTIL, BYMONTH, BYWEEKNO, BYYEARDAY, BYMONTHDAY, BYDAY (星期一在前), BYSETPOS, WKST (为 MO 时省略), 列表排序并去重.

  • 规则的起点是闹钟的 date, 响铃时刻由 time 决定, 排除的日期写在 exclude 中.
  • 支持 FREQ 为 DAILY, WEEKLY, MONTHLY, YEARLY. 不支持 SECONDLY, MINUTELY, HOURLY, BYHOUR, BYMINUTE, BYSECOND (一个闹钟每天只有一个由 time 决定的响铃时刻), 也不支持写在规则中的 DTSTART (改用 date), EXDATE (改用 exclude), RDATE 与 EXRULE. 遇到时抛出 INVALID_RULE, 消息中写明不支持的部分.
  • 不允许的组合: COUNT 与 UNTIL 同时出现; BYWEEKNO 或 BYYEARDAY 不配 YEARLY; BYMONTHDAY 配 WEEKLY; 带序数的 BYDAY (如 2TU) 不配 MONTHLY 或 YEARLY, 或与 BYWEEKNO 同用; 只有 BYSETPOS 而没有其他 BY 部分.
  • 取值范围: BYMONTH 为 1..12; BYMONTHDAY 为 1..31 或 -31..-1; BYYEARDAY 为 1..366 或其负数; BYWEEKNO 为 1..53 或其负数; BYDAY 的序数在 MONTHLY 中为 1..5 或其负数, 在 YEARLY 中为 1..53 或其负数; BYSETPOS 为 1..366 或其负数. 负数从末尾倒数.
  • 不存在的日期按 RFC 5545 跳过, 例如 BYMONTHDAY=31 在只有 30 天的月份不响; 想要 "每月最后一天" 用 BYMONTHDAY=-1.
  • UNTIL 为 yyyyMMdd 或 yyyyMMddTHHmmss[Z]; 结构化规则的 until 写 'YYYY-MM-DD' 时转为 yyyyMMdd, 写 Date 或时间戳时转为 UTC 时刻.

常见写法:

需求 repeat 规范形式
每天 'FREQ=DAILY' 或 { freq: 'daily' } FREQ=DAILY
周一至周五 [1, 2, 3, 4, 5] FREQ=WEEKLY;BYDAY=MO,TU,WE,TH,FR
周末 [0, 6] FREQ=WEEKLY;BYDAY=SA,SU
每 3 天 (轮班, 起点为 date) { freq: 'daily', interval: 3 } FREQ=DAILY;INTERVAL=3
隔周星期一 'FREQ=WEEKLY;INTERVAL=2;BYDAY=MO' 同左
每月 15 日 'FREQ=MONTHLY;BYMONTHDAY=15' 同左
每月最后一天 { freq: 'monthly', byMonthDay: [-1] } FREQ=MONTHLY;BYMONTHDAY=-1
每月第 2 个星期二 'FREQ=MONTHLY;BYDAY=2TU' 同左
每月最后一个星期五 'FREQ=MONTHLY;BYDAY=-1FR' 同左
每月最后一个工作日 (周一至周五) 'FREQ=MONTHLY;BYDAY=MO,TU,WE,TH,FR;BYSETPOS=-1' 同左
每年 3 月 8 日 { freq: 'yearly', byMonth: [3], byMonthDay: [8] } FREQ=YEARLY;BYMONTH=3;BYMONTHDAY=8
每天, 共 10 次 { freq: 'daily', count: 10 } FREQ=DAILY;COUNT=10
每天, 到 2026 年底为止 { freq: 'daily', until: '2026-12-31' } FREQ=DAILY;UNTIL=20261231

选项 (Options)#

AlarmOptions#

alarms.add, alarms.preview 与 alarms.update 的选项. 省略的 sound.source, vibrate, snooze (包括只省略 minutes 或 max) 与 autoSilenceMinutes 不保存在闹钟中, 响铃时取插件设置页的默认值 (出厂为默认铃声, 振动, 贪睡 10 分钟至多 3 次, 10 分钟后自动停止); 改动设置只影响之后的响铃.

  • [ time ] { string | {{ hour: number; minute: number; second?: number }} } - 响铃的墙上时间, '07:30', '07:30:15' 或对象形式; 与 at 二选一
  • [ date ] { string | Date | number } - 一次性闹钟的日期, 或重复规则的起始日, 'YYYY-MM-DD', Date 或时间戳 (按闹钟的时区取日期); 省略时由插件补上, 见 add
  • [ at ] { Date | number } - 一次性闹钟的绝对时刻; 与 time 二选一, 不能与 date 或 repeat 同用
  • [ repeat ] { string | RepeatRule | number[] } - 重复规则, 见 重复规则; 省略即一次性闹钟
  • [ exclude ] { (string | Date | number)[] } - 不响铃的日期, 至多 366 个
  • [ timeZone ] { string | null } - IANA 时区 ID, 如 'Asia/Shanghai'; 省略或为 null 时跟随设备时区
  • [ label ] { string } - 标签, 至多 100 个字符
  • [ enabled = true ] { boolean } - 是否启用
  • [ tag ] { string } - 脚本自用的分组文字, 至多 100 个字符, AlarmFilter 可按它筛选
  • [ sound ] { SoundOptions } - 铃声
  • [ vibrate ] { boolean | number[] } - 振动: true 按默认节奏 [0, 600, 400] 循环; 数组为自定义节奏, 写法同 device.vibrate (等待, 振动, 等待, 振动, ... 毫秒), 1 - 64 项, 不能为负且不能全为 0; false 不振动. 振动以闹钟用途发出, 勿扰模式下仍振动
  • [ speak ] { SpeakOptions } - 朗读
  • [ snooze ] { boolean | {{ minutes?: number; max?: number }} } - 贪睡: false 不允许贪睡; true 或对象允许贪睡, minutes 为每次贪睡的分钟数 (1..60), max 为一轮至多贪睡的次数 (1..10)
  • [ autoSilenceMinutes ] { number } - 无人处理时响多久自动停止 (分钟), 范围 1..60; 停止时发出 silence 事件
  • [ holidays ] { HolidayFilter | null } - 节假日过滤, 需要插件的 holidays 功能 (插件 1.0.0 不提供, 给出非 null 值时抛出 PLUGIN_INCOMPATIBLE)
  • [ dismiss ] { DismissOptions | null } - 关闭方式, 需要插件的 challenges 功能 (插件 1.0.0 不提供, 给出非 null 值时抛出 PLUGIN_INCOMPATIBLE)

RepeatRule#

结构化的重复规则, 各键对应 RRULE 的同名部分, 见 重复规则.

  • freq { 'daily' | 'weekly' | 'monthly' | 'yearly' } - 频率
  • [ interval = 1 ] { number } - 每隔几个周期
  • [ count ] { number } - 总次数, 与 until 二选一
  • [ until ] { string | Date | number } - 截止日期或时刻
  • [ byMonth ] { number[] } - 月份 1..12
  • [ byWeekNo ] { number[] } - 一年中的第几周, 只用于 'yearly'
  • [ byYearDay ] { number[] } - 一年中的第几天, 只用于 'yearly'
  • [ byMonthDay ] { number[] } - 一月中的第几天, 负数从月末倒数 (-1 为最后一天)
  • [ byDay ] { (number | string)[] } - 星期: 编号 0..6, 或 RRULE 写法 'MO', '2TU' (第 2 个星期二), '-1FR' (最后一个星期五)
  • [ bySetPos ] { number[] } - 在每个周期的候选日中取第几个, 负数从末尾倒数
  • [ weekStart = 1 ] { 0 | 1 } - 一周的第一天, 0 为星期日, 1 为星期一

SoundOptions#

  • [ source ] { string } - 铃声来源:
    • 'default': 系统默认闹钟铃声 (省略时取插件设置的默认铃声, 出厂为它);
    • 'silent': 不出声, 只振动或只朗读;
    • 铃声 URI, 如 ringtones.list 给出的 uri;
    • 本地音频文件路径或 file:// URI: AutoJs6 以只读方式打开文件交给插件, 插件把它复制进自己的存储后使用 (之后删除原文件不影响响铃), 文件至多 20 MiB, 必须含可解码的音轨; 内容相同的文件只导入一次, 插件中至多保存 500 个导入的铃声. 导入后的 source 形如 chime-ringtone://imported/<id>.
  • [ volume ] { number } - 独立音量 0..1; 省略时用当前的闹钟音量. 响铃期间临时调整闹钟音量, 结束后恢复用户原来的音量; 0 为静音
  • [ rampSeconds = 0 ] { number } - 渐强时长 (秒), 0..300, 0 不渐强

铃声无法播放时 (文件损坏, 权限丢失等), 插件依次退回到默认闹钟铃声, 默认来电铃声, 默认通知音, 最后用提示音, 闹钟总会出声.

SpeakOptions#

响铃时朗读文字. 朗读使用系统 TTS 引擎接口, 可以指定任一已安装的 TTS 引擎, 如 3-Macaw Speech.

  • text { string } - 朗读的文字, 1 - 500 个字符, 不能只有空白
  • [ engine ] { string } - TTS 引擎包名, 如 'io.github.supermonster003.autojs6.plugin.three.macaw.speech'; 省略时用系统默认引擎
  • [ language ] { string } - 语言, BCP 47 标签, 如 'zh-CN'
  • [ rate ] { number } - 语速, 大于 0
  • [ pitch ] { number } - 音调, 大于 0
  • [ mode = 'after' ] { 'before' | 'after' | 'interleave' | 'only' } - 朗读与铃声的配合:
    • 'after': 铃声先响 5 秒再朗读, 朗读时铃声压低到 0.25 倍;
    • 'before': 先在无铃声时朗读, 读完再响铃, 之后的朗读同样压低铃声;
    • 'interleave': 铃声响一段 (repeatInterval 秒, 为 0 时 10 秒) 后停下朗读, 如此交替;
    • 'only': 只朗读, 不放铃声.
  • [ repeatInterval = 0 ] { number } - 重复朗读的间隔 (秒), 0..3600; 除 'interleave' 外, 0 只读一次, 否则在上一次读完后间隔这么久再读

朗读不可用时照常发声: 指定的引擎未安装 (不会改用系统默认引擎), 引擎 10 秒内未就绪, 不支持该语言等情形放弃这一轮的朗读; 本身不出声的设置 ('silent', 'only') 此时改为播放铃声.

HolidayFilter#

节假日过滤, 需要插件的 holidays 功能 (插件 1.0.0 不提供).

  • [ region ] { string } - 地区, ISO 3166-1 两位代码, 可带下级地区, 如 'CN', 'US-CA'
  • mode { 'skip' | 'only' | 'workdays' } - 'skip' 去掉节假日; 'only' 只在节假日响; 'workdays' 在每个工作日响 (此时 repeat 只能省略或为间隔 1 的 daily)

DismissOptions#

关闭挑战, 需要插件的 challenges 功能 (插件 1.0.0 不提供).

  • [ challenge = 'none' ] { 'none' | 'math' | 'shake' | 'type' | 'script' } - 关闭方式
  • [ math ] { { difficulty?: number; count?: number }} - 算术题的难度 (1..3) 与题数 (1..20)
  • [ shake ] { { count?: number }} - 摇晃次数 (1..300)
  • [ type ] { { text?: string }} - 需要输入的文字, 至多 200 个字符
  • [ script ] {{ fallback?: 'none' | 'math' | 'shake' | 'type' }} - 脚本条件无法执行时的退路
  • [ allowSnooze ] { boolean } - 挑战期间是否允许贪睡

AlarmFilter#

alarms.list 与 alarms.upcoming 的筛选条件, 各条件同时满足.

  • [ source ] { string | string[] } - 创建来源, 'user', 'script', 'tool' 或 'intent', 数组为其中任一; 按创建来源而不是最后修改来源筛选
  • [ tag ] { string } - 与 tag 完全相同
  • [ enabled ] { boolean } - 启用状态
  • [ label ] { string | RegExp } - 字符串为完全相同, 正则表达式为包含匹配 (由 AutoJs6 在结果上筛选)

BindOptions#

alarms.bind 的选项.

  • [ events = ['ring'] ] { AlarmEventName | AlarmEventName[] } - 启动脚本的事件, 不能为空数组
  • [ leadSeconds = 60 ] { number } - beforeRing 的提前量 (秒), 15..300; 只在 events 含 beforeRing 时允许写, 否则抛出 INVALID_OPTIONS

alarms.upcoming 的元素.

  • alarmId { string } - 闹钟 ID
  • label { string | null } - 标签
  • at { number } - 响铃时刻

Ringing#

alarms.ringing 的元素.

  • id { string } - 闹钟 ID
  • kind { 'alarm' | 'timer' } - 类别, 插件 1.0.0 只有 'alarm'
  • label { string | null } - 标签
  • since { number } - 这一轮开始的时刻
  • snoozed { boolean } - 是否在贪睡中
  • snoozeCount { number } - 本次计划响铃已贪睡的次数
  • challenge { string | null } - 关闭挑战, 插件 1.0.0 为 null

Ringtone#

alarms.ringtones.list 的元素.

  • uri { string } - 用作 sound.source 的 URI
  • title { string } - 名称; 导入的铃声为文件名去掉扩展名
  • source { 'system' | 'imported' } - 系统铃声或导入的铃声
  • default { boolean } - 是否为系统默认闹钟铃声

Binding#

alarms.bind 与 alarms.bindings 的结果.

  • alarmId { string } - 闹钟 ID
  • script { string } - 脚本的绝对路径
  • events { AlarmEventName[] } - 启动脚本的事件
  • [ leadSeconds ] { number } - beforeRing 的提前量, 只在 events 含 beforeRing 时存在

AlarmEvent#

闹钟事件, 即 alarms.on 回调的参数, engines.myEngine().execArgv.alarm 与 alarms.currentEvent 的值. 事件名 (AlarmEventName) 为 'beforeRing', 'ring', 'snooze', 'dismiss', 'silence', 'miss', 'skip' 与 'change', 见 事件.

  • type { string } - 事件名
  • kind { 'alarm' | 'timer' } - 类别, 插件 1.0.0 只有 'alarm'
  • alarmId { string } - 闹钟 ID
  • label { string | null } - 标签; change 的 remove 为删除前的标签
  • scheduledAt { number | undefined } - 这一轮应响的时刻, 贪睡后再响为贪睡结束的时刻; change 没有此字段
  • firedAt { number } - 事件发生的时刻
  • occurrence { string } - 这一轮响铃的标识, 至多 128 个字符, 见 事件
  • [ snoozeCount ] { number } - ring, snooze: 已贪睡的次数
  • [ by ] { 'user' | 'script' | 'tool' | 'challenge' } - snooze, dismiss: 操作来源
  • [ minutes ] { number } - snooze: 贪睡分钟数
  • [ challenge ] { string | null } - dismiss: 关闭挑战
  • [ ringMillis ] { number } - silence: 响了多久 (毫秒)
  • [ reason ] { string } - miss: 'off' 或 'late'; skip: 'skipNext', 'holiday' 或 'script'
  • [ detail ] { string } - skip 且 reason 为 'script' 时的原因
  • [ action ] { 'add' | 'update' | 'remove' } - change: 变更类别
  • [ source ] { 'user' | 'script' | 'tool' | 'intent' } - change: 变更来源
  • [ deadline ] { number } - beforeRing: 作出决定的截止时刻
alarms.on('miss', (e) => {
    console.warn(`错过 ${e.label} (${new Date(e.scheduledAt).toLocaleString()}), 原因 ${e.reason}`);

AlarmSubscription#

alarms.on 与 alarms.once 的返回值.

  • event { AlarmEventName } - 监听的事件名
  • off { () => void } - 注销这个监听器; 重复调用无效果

AlarmCapabilities#

alarms.capabilities 的返回值.

  • pluginVersionName { string | null } - 插件版本名称
  • pluginVersionCode { number } - 插件版本号
  • packageName { string } - 插件包名
  • contractVersion { number } - 闹钟插件契约版本, 现为 1
  • features { string[] } - 插件实现的功能: alarms (闹钟, 插件 1.0.0 只有它), 以及计划中的 timers, stopwatch, holidays, beforeRing 与 challenges; 应按它判断能力, 不要假定所有功能都存在
  • permissions { { exactAlarm: boolean; notifications: boolean; fullScreen: boolean }} - 插件当前持有的精确闹钟, 通知与全屏通知权限
  • holidayDataVersion { string | null } - 节假日数据版本, 没有 holidays 功能时为 null
  • warnings { string[] } - 需要用户注意的情况, 没有时为空数组
  • limits { object } - 契约限制值: maxAlarms, maxEnabledAlarms, maxTimers, maxBindingsPerAlarm, maxLabelChars, maxTagChars, maxSpeakTextChars, maxRingtoneBytes, maxPreviewCount, maxUpcomingCount, maxExcludeDates, maxVibratePattern, minAutoSilenceMinutes, maxAutoSilenceMinutes, minSnoozeMinutes, maxSnoozeMinutes, maxSnoozeCount, maxRampSeconds, minLeadSeconds, maxLeadSeconds, 数值见 限制

错误代码#

代码 含义
PLUGIN_UNAVAILABLE 未安装 3-Chime Alarm, 或插件不应答
PLUGIN_DISABLED 插件已在插件中心停用或未授权
PLUGIN_INCOMPATIBLE 插件版本或契约版本不兼容, 或插件未声明该调用所需的功能 (例如插件 1.0.0 上的 holidays 与 dismiss 选项, beforeRing 事件)
PERMISSION_REQUIRED 调用会留下启用的闹钟, 而插件没有精确闹钟权限 (Android 12 - 12L); hint 为 alarms.openPlugin('permissions'). 缺少通知或全屏通知权限不会让调用失败
INVALID_OPTIONS 选项未知, 类型错误, 缺少必填项或超出取值范围; 消息写明选项名
INVALID_RULE 重复规则格式错误或使用了不支持的部分
NOT_FOUND 闹钟 ID 不存在 (update, setEnabled, skipNext, cancelSkip, bind)
LIMIT_EXCEEDED 超出 限制 中的长度, 大小或数量上限
NO_HANDLER 没有应用能处理该系统时钟 Intent (仅 alarms.system)

HOLIDAY_DATA_MISSING 请求的地区没有节假日数据 (需要 holidays 功能)
TIMEOUT 插件未在时限内应答
SESSION_CLOSED 调用期间插件进程退出, 或操作被取消
INTERNAL 其他内部错误

let a = alarms.add({
    time: '07:30',
    repeat: [1, 2, 3, 4, 5],
    label: '起床',
    sound: { source: 'default', volume: 0.8, rampSeconds: 30 },
    vibrate: [0, 500, 500, 500],
    snooze: { minutes: 9, max: 3 },
});
a.bind('./after-wake.js', { events: ['dismiss'] });

/* after-wake.js */
let e = alarms.currentEvent();

    toastLog('早上好');
}

if (!alarms.isAvailable()) {
    toastLog('请在插件中心安装并启用 3-Chime Alarm');
    exit();

try {
    alarms.add({ at: Date.now() + 10 * 60 * 1000, label: '泡面好了' });
} catch (e) {
    if (e instanceof alarms.AlarmError && e.hint !== null) {
        toastLog(`${e.code}: ${e.hint}`);
    } else {
        throw e;
    }
}
