表格 (Xlsx)#

运行时支持 Rhino Node.js 主线程 Node.js Worker Bun
入口 xlsx autojs6:xlsx, $autojs.xlsx autojs6:xlsx, $autojs.xlsx host.xlsx
状态 已支持 42 项 已支持 42 项 已支持 42 项 需授权 42 项
授权 - - - xlsx.control 42 项

各 API 在同一运行时中的入口, 状态与授权一致, 没有差异项.

Node.js 与 Bun 的导入方式, 异步返回值与授权检查见 运行时 API.

xlsx 模块用于在脚本中读写电子表格: 读取工作簿信息与单元格数据, 整体写出或在末尾追加行, 打开工作簿后编辑工作表, 行列, 单元格, 样式, 合并单元格, 超链接, 批注, 图片, 条件格式与数据有效性, 用流式写出器生成大表, 以及在格式之间转换, 合并, 拆分, 去重, 重算公式, 加密与解密, 探测 csv 的编码与分隔符, 打开插件的表格查看器并接收选中事件. 支持的格式为 xlsx, xlsm, xls, csv 与 tsv.

从 AutoJs6 6.8.1 起, 本模块由外置 3-Tally Sheet 插件 (AutoJs6-Plugin-Three-Tally-Sheet) 1.0.0 及以上版本提供. 调用前需在插件中心安装并启用与当前 AutoJs6 兼容的插件. 插件缺失, 被禁用或版本不兼容时, 方法抛出 (或以 Promise 拒绝) code 为 PLUGIN_UNAVAILABLE, PLUGIN_DISABLED 或 PLUGIN_INCOMPATIBLE 的 XlsxError, 消息以 "3-Tally Sheet 插件不可用. 请在插件中心安装, 启用或更新后重试." 开头. xlsx.isAvailable 可预先探测. 由 AutoJs6 打包的应用同样可以使用本模块, 前提是运行它的设备已安装 3-Tally Sheet 1.0.0 及以上版本, 应用由 AutoJs6 6.8.1 及以上版本打包, 且带有 org.autojs.plugin.xlsx.permission.RUNTIME 权限. 打包流程为 Node.js 项目 (声明了 files 能力或未强制能力) 与 Bun 项目 (授予了 xlsx.control) 自动加入该权限; Rhino 项目需要在 project.json 的 permissions 中加入它. 打包应用经插件单独的服务与查看器入口调用, 打开的工作簿, 写出器与查看器会话只允许创建它们的应用调用.

本模块在 Rhino 中注册为全局名称 xlsx, 并提供 $xlsx 别名, 二者指向同一对象. 本页的签名与同步返回值描述 Rhino. Node.js, Bun 与 Node.js Worker 提供显式导入的异步接口, 参阅 Runtime APIs 的 xlsx.

let path = '/sdcard/Documents/sales.xlsx';
let info = xlsx.info(path);
info.sheets.forEach(s => console.log(s.name, s.rows + ' 行', s.cols + ' 列'));
let items = xlsx.read(path, { header: true, limit: 3 });
items.forEach(item => console.log(JSON.stringify(item)));
let result = xlsx.write('./summary.xlsx', [['城市', '销量'], ['杭州', 120], ['苏州', 95]], {
    header: true, columnWidths: 'auto', freeze: 1,
});
console.log(result.path, result.sheets[0].rows); // ./summary.xlsx 的绝对路径, 3

准备工作#

  1. 在插件中心安装并启用 3-Tally Sheet. 1.0.0 要求 AutoJs6 6.8.1 (版本号 6641) 及以上版本, 版本不满足时调用失败于 PLUGIN_INCOMPATIBLE.
  2. 授予 AutoJs6 存储权限. 输入与输出文件都由 AutoJs6 打开, 再以文件描述符交给插件, 插件不会得到任何路径, 也不需要自己的存储权限. AutoJs6 没有权限读写某个文件时调用失败于 STORAGE_PERMISSION_DENIED, 其他读写失败为 IO_ERROR.
  3. 使用 view 时, AutoJs6 需要处于前台 (有可见的界面, 系统为 Android 10 以下, 或 AutoJs6 有悬浮窗权限).

路径与输出#

输入文件以路径指定, 相对路径按脚本工作目录解析 (与 files.path 相同), 也可使用绝对路径. 不接受 content:// URI (失败于 INVALID_ARGUMENT, 消息形如 "'read path' must be a file path; content:// URIs are not accepted"). 路径不是已存在的普通文件时失败于 FILE_NOT_FOUND.

文件格式由扩展名与文件头共同判断: .xlsx, .xlsm, .xls, .csv 与 .tsv 按扩展名识别, 内容与扩展名不符或无法识别时失败于 INVALID_FILE; 扩展名不常见时可用选项 format 指定 ('xlsx', 'xlsm', 'xls', 'csv' 或 'tsv', 不区分大小写, 其他值失败于 UNSUPPORTED_FORMAT). tsv 是以制表符分隔的 csv.

write, writeAll, append, createWriter 与 Workbook#save 的目标路径必须给出, 格式取选项 format, 其次取目标的扩展名, 都没有时失败于 UNSUPPORTED_FORMAT.

convert, toCsv, merge, split, dedupe, encrypt 与 decrypt 的第二个参数是可选的输出路径 (split 为输出目录):

  • 字符串: 输出路径, 相对路径同样按脚本工作目录解析.
  • null 或 undefined: 使用默认输出, 但占用这个参数位置, 后面可以继续传选项.
  • 对象且后面没有第三个参数: 视为省略输出, 该对象是选项. 例如 xlsx.dedupe(path, { columns: [1] }) 与 xlsx.dedupe(path, null, { columns: [1] }) 相同.

recalc 的输出由选项 output 给出. 默认输出位于 /sdcard/Documents/3-Tally Sheet/ (外部存储的 Documents 目录), 文件名为 <源名>-<操作>-<yyyyMMdd-HHmmss>.<扩展名>, 重名时依次追加 -2, -3 等; split 的默认输出目录同样命名, 不带扩展名. 源名为输入文件名去掉扩展名 (merge 取第一个输入), 为空时为 sheet. 操作名为方法名 (convert, toCsv, merge, split, dedupe, recalc, encrypt, decrypt), 扩展名为输出格式.

输出的写入方式:

  • 显式给出的输出文件已存在时被覆盖, 输出也可以是输入文件本身. write 与 writeAll 总是写出一个新文件, 替换目标路径上已有的文件.
  • 结果先写入同目录的隐藏文件 .<文件名>.<时间戳>.tmp, 完成后改名为目标文件; 调用失败或被取消时删除该文件, 目标路径下不会留下不完整的文件.
  • 输出路径是已存在的目录时失败于 INVALID_ARGUMENT. 父目录不存在时自动创建, 无法创建时失败于 IO_ERROR.
  • split 的输出目录不存在时自动创建. 目录中已有同名文件时, 新文件依次追加 -2, -3 等, 不覆盖已有文件.

行列编号与数据模型#

行号与列号都从 1 计 (第 1 行, 第 1 列即 A1).

  • 列可以写作字母 ('A', 'AA', 不区分大小写, 1 至 3 个字母) 或数字 (1 至 16384).
  • 单元格引用为 A1 形式, 如 'B4'.
  • 范围为 A1 形式的单个单元格, 矩形 ('A1:D20'), 整列 ('B:B', 'B:D') 或整行 ('3:3', '3:5'). 两个角可以任意顺序书写, 会被规范为左上与右下. 格式不对或超出格式上限 (xlsx 为 1,048,576 行, 16,384 列; xls 为 65,536 行, 256 列) 时失败于 RANGE_INVALID.
  • 工作表以名称或从 1 计的序号指定 (选项 sheet), 省略时为第一个可见的工作表. 工作表不存在时失败于 SHEET_NOT_FOUND. 名称至多 31 个字符.

读取得到的行默认为数组的数组, 每行是一个数组, 行内缺失的列补 null. 选项 header: true 把范围的第一行作为表头, 其余各行返回以表头文字为键的对象; 表头重复的键依次加后缀 _2, _3 等, 第 n 个空表头的键为 __EMPTY_n (从 1 计).

单元格的值 (CellValue):

单元格 读到的值 写入时
数字 number 数字写为数字单元格. NaN 与无穷大失败于 INVALID_ARGUMENT
文本 string 字符串写为文本. 以 = 开头的字符串只有在选项 formulas: true 时才作为公式
布尔 boolean 布尔值写为布尔单元格
日期与时间 Date Date 写为日期单元格, 数字格式默认 yyyy-mm-dd hh:mm:ss, 可用选项 dateFormat 改变
空单元格 null null 或 undefined 清除值, 保留已有样式
错误 错误文本, 如 '#DIV/0!' -
公式 缓存的计算结果 { f: 'SUM(A1:A3)' } 写入公式 (= 可省略)

日期按设备当前时区解释: 读取时把单元格的日期与时间视为设备本地时间, 写入时存入 Date 在设备时区下的本地日期与时间, 二者在同一设备上往返不变. 工作簿使用 1904 日期系统时同样按其标志换算, info 的 dateSystem 报告它.

选项 formatted: true 让各单元格返回显示文本 (按数字格式与公式结果格式化的字符串). 选项 cells: true 让各单元格返回 CellDetail 对象, 其中带有值, 公式, 类型, 显示文本与样式 id.

读取模式与大表#

open 与读取类方法的选项 mode 决定插件如何载入工作簿:

  • 'auto' (默认): 单元格总数不超过整载上限时整体载入, 否则以流式读取.
  • 'full': 整体载入. 超过整载上限时失败于 LIMIT_EXCEEDED.
  • 'stream': 流式读取, 内存占用与表的大小无关.

整载上限取以下两者的较小值:

  • 1,000,000 个单元格.
  • 插件进程剩余 Java 堆的 90% 能容纳的单元格数 (按每个单元格约 750 字节估算). 剩余内存不足时, 较小的表也会改为流式读取; mode: 'full' 则失败于 LIMIT_EXCEEDED, 消息提到剩余的 Java 堆. 流式读取不受这一限制.

csv 与 tsv 按开头 64 KB 的样本估算单元格数, 再按同样的规则选择模式.

流式打开的工作簿只能按行顺序读取:

  • Sheet#read, Sheet#eachRow, Sheet#cell, Sheet#find 与信息查询可用.
  • 所有修改, Workbook#save 与 Workbook#recalc 失败于 READ_ONLY; 读取条件格式与数据有效性失败于 UNSUPPORTED.
  • 共享公式的单元格在 cells: true 时不带 f.

读取大表时, 使用 Sheet#eachRow 分批处理 (每批至多 1000 行), 或用 range, from / to 与 limit 只取需要的行; 生成大表时, 使用 createWriter 逐行写出 (插件只在内存中保留最近 100 行). 行数据在 AutoJs6 与插件之间分块传递, 每块至多 1000 行或 512 KiB, 单行超过 32 MiB 时失败于 LIMIT_EXCEEDED.

同步, 异步与进度#

除 isAvailable 外, 每个方法都有同步形态 x(...) 与异步形态 xAsync(...), 二者参数与结果一致. 默认没有超时, 调用一直等待到插件返回结果, 失败或被取消.

  • 同步形态阻塞当前脚本线程直至插件返回结果或调用失败. 在 UI 线程调用会阻塞界面, UI 模式中请使用 Async 形态. 停止脚本会取消尚未完成的调用.
  • 异步形态立即返回 Promise, 回调在脚本线程执行. 参数错误同样以 Promise 拒绝体现, 不同步抛出. 返回的 Promise 带有不可枚举, 只读的 cancel() 方法: 调用仍在进行时返回 true 并取消任务, 之后 Promise 以 CANCELLED 拒绝; 调用已结束时返回 false.
  • options 必须是对象, 未知的选项键失败于 INVALID_ARGUMENT (消息形如 "read does not know the option 'x'; known: ..."). 参数个数不在签名范围内时同样失败于 INVALID_ARGUMENT (消息形如 "... takes at most 3 argument(s), got 4").

报告进度的调用接受选项 onProgress, 它在脚本线程收到 Progress 对象, 至多每 100 毫秒一次. 报告进度的有 write, writeAll, append, convert, toCsv, merge, split, dedupe, recalc, encrypt, decrypt, sniff, Workbook#saveAsync 与 Writer#closeAsync 的 Async 形态; 其他 Async 方法接受但不使用 onProgress. 同步形态不接受 onProgress (失败于 INVALID_ARGUMENT, 消息形如 "'write' does not take 'onProgress'; writeAsync reports progress").

let job = xlsx.mergeAsync(['./a.xlsx', './b.xlsx'], './ab.xlsx', {
    mode: 'rows',
    onProgress: p => console.log(p.stage, p.percent < 0 ? '?' : p.percent + '%'),
});
job.then(r => console.log(r.path, r.sheets[0].rows)).catch(e => console.error(e.toString()));
setTimeout(() => job.cancel(), 5000);

每个脚本同时至多持有 16 个打开的工作簿与写出器 (合计, 超出时失败于 TOO_MANY_HANDLES), 插件同时至多执行 2 个耗时操作 (写出, 转换, 合并等), 其余排队等待.

csv 与编码#

csv 与 tsv 按 RFC 4180 读写: 字段可用双引号包围, 引号内可以有分隔符与换行, 引号本身写作两个双引号. 读取时的工作表名称为文件名去掉扩展名 (截断到 31 个字符), 为空时为 Sheet1.

读取时的编码:

  • 给出选项 encoding (Java 字符集名称, 如 'UTF-8', 'GBK', 'GB18030', 'Big5', 'Shift_JIS', 'UTF-16LE') 时直接使用, 不做探测; 未知的名称失败于 INVALID_ARGUMENT. 'UTF-16' 读取时按 BOM 的字节序.
  • 否则依次判断: 文件开头的 BOM (UTF-8, UTF-16LE, UTF-16BE); 按零字节的比例识别不带 BOM 的 UTF-16; 样本是否为严格合法的 UTF-8 (纯 ASCII 视为 UTF-8); 统计探测 (GBK 文本得到 GB18030, 以及 Big5, Shift_JIS, windows-125x 等).
  • 以上都没有结论时 (例如很短的 GBK 文件), 使用插件设置页 "CSV" 分组中的 "读取默认编码" (默认 GB18030; 读取设置失败时同样为 GB18030). 很短但合法的 UTF-8 文件仍按 UTF-8 读取.

分隔符: 给出选项 delimiter (单个字符) 时直接使用; 否则在开头 64 KB 中对 ,, ;, 制表符与 | 按各行列数的一致性评分选出 (考虑引号). tsv 默认使用制表符. sniff 返回探测得到的编码, 分隔符与有无 BOM, 不读取全部内容.

读取时的值:

  • parseNumbers (默认 true): 能解析为数字的字段转为数字. 带多余前导零的 (如 '007', 但 '0' 与 '0.5' 可以) 或有效数字超过 15 位的 (如身份证号与长订单号) 保持字符串, 以免丢失精度.
  • parseBooleans (默认 false): 为 true 时把 TRUE 与 FALSE 转为布尔值.
  • 日期不做转换, 保持字符串.

写出时默认使用 UTF-8 并带 BOM (Excel 据此识别 UTF-8), 分隔符为 , (tsv 为制表符). 选项 encoding, bom: false 与 delimiter 可以改变; 'UTF-16' 写出为带 BOM 的 UTF-16LE. 插件设置页的 "写出默认编码" 与 "写出时带 BOM" 只决定插件工具箱的初始选项, 不影响脚本. csv 与 tsv 只能保存一个工作表 (写入多个时失败于 UNSUPPORTED), 不保存样式, 公式与版式: write 与 writeAll 给出版式选项或 password 时, 以及 append 给出版式选项时, 失败于 INVALID_ARGUMENT; createWriter 写入的样式与公式只在结果的 warnings 中说明.

let probe = xlsx.sniff('./legacy.csv');
console.log(probe.encoding, JSON.stringify(probe.delimiter), probe.hasBom); // GB18030 "," false
let rows = xlsx.read('./legacy.csv', { header: true, encoding: probe.encoding });
xlsx.convert('./legacy.csv', './legacy-utf8.csv', { encoding: 'UTF-8', bom: true });

公式#

读取时公式单元格返回其缓存的计算结果; cells: true 时 CellDetail 的 f 为公式文本 (不带 =), formatted: true 时为显示文本. 流式读取的共享公式单元格不带 f.

写入公式有两种方式: 值为 { f: 'SUM(B2:B9)' } 对象 (= 可省略), 或者以 = 开头的字符串并给出选项 formulas: true. 公式有语法错误时失败于 FORMULA_ERROR, 错误的 sheet 与 ref 指出位置.

保存时的计算:

  • 有值的改动 (写入行, 设置单元格, 行列或工作表操作) 后保存时, 插件计算公式并写入缓存值, 使其他程序不必重算即可读到结果. 只改样式, 工作表属性, 规则或版式时不计算. 选项 evaluate: false 跳过计算, 并让 Excel 打开文件时重算.
  • 插件不能计算的函数 (例如 INFO, CELL, N, DATEDIF) 与无法解析的公式: 保留公式, 清空缓存值, 设置打开时重算, 并在 warnings 中说明.
  • 引用其他工作簿的公式不计算, 保留原缓存值并给出警告.
  • 循环引用 (及依赖它的公式) 的缓存值为 #VALUE!, 并给出警告; 其他 Excel 错误 (#REF!, #DIV/0!, #N/A 等) 照常作为结果.
  • 引用链过深导致计算失败时失败于 FORMULA_ERROR, 消息建议使用 evaluate: false.

xlsx.recalc 与 Workbook#recalc 不论有无改动都重算全部公式. createWriter 写出的公式不计算, 文件被设置为打开时重算. 警告文本由计算引擎生成, 为英文.

加密与密码#

xlsx, xlsm 与 xls 可以加密, csv 与 tsv 不能.

  • 打开加密文件时用选项 password 传入密码. 未给密码时失败于 PASSWORD_REQUIRED, 密码错误时失败于 WRONG_PASSWORD. 对未加密的文件给出的密码被忽略.
  • info 与 Workbook#info 的 encrypted 只在以密码打开了加密文件时为 true.
  • 保存 (Workbook#save, append, recalc, convert, dedupe, split 等) 时沿用打开时的密码. xlsx 与 xlsm 总是以 Agile 加密 (AES-256, SHA-512) 保存; xls 沿用原加密方式, 新加密的 xls 使用 RC4 CryptoAPI.
  • Workbook#save 的 password 为非空字符串时以它重新加密, 为 '' 或 null 时去掉加密.
  • 输出为 csv 或 tsv 时总是明文, 结果的 warnings 说明去掉了加密; 此时显式给出非空的输出密码失败于 UNSUPPORTED (save) 或 INVALID_ARGUMENT (merge 的 outputPassword).
  • write, writeAll 与 createWriter 的 password 加密新文件. 写出器只能加密 xlsx.
  • merge 以 passwords 为各输入分别给出密码, 以 outputPassword 决定输出的密码, 见该方法.
  • encrypt 与 decrypt 为已有文件加上或去掉密码.

样式与版式#

StyleSpec#

样式规格对象, 用于 Sheet#setStyle, Workbook#createStyle, Sheet#set 与 Sheet#setRows 的 style, Writer#addRow 的 style, 以及 LayoutOptions 的 styles. 各键都可省略, 设置到已有样式上时只改给出的键, 未知的键失败于 INVALID_ARGUMENT.

  • font {{
    • name?: string;
    • size?: number;
    • bold?: boolean;
    • italic?: boolean;
    • underline?: boolean | 'none' | 'single' | 'double' | 'singleAccounting' | 'doubleAccounting';
    • strike?: boolean;
    • color?: string;
  • }} - 字体. size 为磅值 (大于 0, 至多 409), underline: true 等同 'single'
  • fill { string } - 填充颜色 '#RRGGBB', 'none' 去掉填充
  • border { string | Object } - 四边相同的线型名称, 或 { top, bottom, left, right }, 每边为线型名称或 { style, color }. 线型为 none, thin, medium, thick, dashed, dotted, double, hair, mediumDashed, dashDot, mediumDashDot, dashDotDot, mediumDashDotDot, slantedDashDot
  • align { 'general' | 'left' | 'center' | 'right' | 'fill' | 'justify' | 'centerAcross' | 'distributed' } - 水平对齐
  • valign { 'top' | 'middle' | 'bottom' | 'justify' | 'distributed' } - 垂直对齐
  • wrap { boolean } - 自动换行
  • numFmt { string } - 数字格式, 如 '0.00', '#,##0', '0%', 'yyyy-mm-dd'
  • indent { number } - 缩进, 0 至 250 (xls 为 0 至 15)
  • rotation { number } - 文字角度, -90 至 90, 或 255 (竖排)

颜色写作 '#RRGGBB'. xls 只有调色板颜色, 写入时换为调色板中最接近的颜色. 一个工作簿中不同样式的数目有上限 (xlsx 64,000 个, xls 4,000 个), 超出时失败于 LIMIT_EXCEEDED. 同一样式反复使用时, 先用 Workbook#createStyle 得到样式 id 再传入, 比每次传规格对象更快.

LayoutOptions#

write, writeAll 与 append 接受的版式选项. 版式作用于本次写入的行 (追加时为追加的行) 与工作表已用的列, 按以下顺序应用:

  • styles {{
    • body?: StyleSpec;
    • columns?: Object;
    • header?: StyleSpec;
  • }} - 样式. 先把 body 应用到表头行以外的各行, 再把 columns (键为列字母或列号, 值为样式规格) 应用到各列 (含表头行), 最后把 header 应用到表头行 (只在写入了表头行时). 样式叠加在单元格已有的样式上, 以 dateFormat 写入的日期在 body 下保留其数字格式
  • columnWidths { 'auto' | Array | Object } - 列宽 (字符数, 至多 255). 'auto' 按内容调整写入的各列; 数组按第 1 列起的顺序给出, null 跳过该列; 对象的键为列字母或列号. 单列的宽度为数字或 'auto'
  • rowHeights { Object } - 行高 (磅, 至多 409), 键为工作表行号, 如 { 1: 24 }
  • merges { string | string[] } - 要合并的 A1 范围
  • freeze { number | {{ rows?: number; cols?: number }} } - 冻结窗格, 数字表示冻结的行数
  • autoFilter { boolean | string } - 自动筛选. true 作用于本次写入的区域, 字符串为 A1 范围

rowHeights, merges, freeze 与字符串形式的 autoFilter 使用工作表坐标. csv 与 tsv 目标不接受版式选项 (INVALID_ARGUMENT). 打开的工作簿以 Sheet 的 setStyle, setColumnWidth, merge, freeze 等方法设置同样的内容.

xlsx.write('./report.xlsx', [
    ['商品', '数量', '单价', '金额'],
    ['钢笔', 3, 1.5, { f: 'B2*C2' }],
    ['笔记本', 2, 12, { f: 'B3*C3' }],
], {
    header: true,
    styles: {
        header: { font: { bold: true }, fill: '#DDEBF7', align: 'center' },
        columns: { C: { numFmt: '0.00' }, D: { numFmt: '0.00' } },
    },
    columnWidths: 'auto', freeze: { rows: 1 }, autoFilter: true,
});

条件格式与数据有效性#

xlsx 与 xlsm 支持全部规则; xls 的条件格式只支持 cellIs 与 expression (其他类型与带 numFmt 的样式失败于 UNSUPPORTED), 规则读回时 stopIfTrue 总为 true, 数据有效性支持全部类型. csv 与 tsv 不含规则: 添加失败于 UNSUPPORTED, 读取返回空数组, 清除返回 0. 以 stream 模式打开的工作簿添加或清除规则失败于 READ_ONLY, 读取失败于 UNSUPPORTED.

Sheet#addConditionalFormat 与 Sheet#addValidation 的范围为一个 A1 范围. 读回的规则 (Sheet#conditionalFormats, Sheet#validations) 形如 { range, rule }, 其中 range 可以是以空格分隔的多个矩形 (例如经 Sheet#clearRules 拆分后, 或文件本来如此). 无法映射的规则读回为 { type: 'unknown', description }.

一个单元格至多有一条数据有效性, 添加时先把其单元格从已有的数据有效性中去掉 (与 Excel 相同); 条件格式可以重叠, 按 priority 排序.

ConditionalFormatRule#

条件格式规则. 公共键:

  • type { string } - 规则类型, 见下
  • [ priority ] { number } - 优先级, 正整数, 小者优先. 省略时排在最后; 给出时该优先级及之后的规则依次顺延
  • [ stopIfTrue = false ] { boolean } - 成立时不再应用后面的规则
  • style { Object } - 差异样式, 用于 cellIs, expression, top10, duplicateValues 与 uniqueValues. 只接受 font.color, font.bold, font.italic, fill, border 与 numFmt, 写法同 StyleSpec

各类型:

  • cellIs: 单元格值比较. operator 为 'between' (默认), 'notBetween', 'eq', 'ne', 'gt', 'lt', 'ge', 'le' (也接受 'greaterThan' 等 OOXML 名称, 读回为短名); value 必填, value2 用于 between 与 notBetween. 操作数可为数字, 布尔值, 日期, 以 = 开头的公式或文本.
  • expression: formula 为条件公式 (= 可省略, 读回不带 =).
  • top10: rank 默认 10 (percent 为 true 时 1 至 100, 否则 1 至 1000), bottom 取最小的若干项, percent 按百分比.
  • duplicateValues 与 uniqueValues: 重复值与唯一值.
  • colorScale: colors 为 2 或 3 个颜色, points 为对应的阈值 (默认最小值与最大值, 三色时中间为第 50 百分位).
  • dataBar: color 默认 '#638EC6', showValue (默认 true) 是否显示数值, points 为两个阈值 (默认最小值与最大值).
  • iconSet: set 为图标集名称 (默认 '3TrafficLights1'), 可选 3Arrows, 3ArrowsGray, 3Flags, 3TrafficLights1, 3TrafficLights2, 3Signs, 3Symbols, 3Symbols2, 4Arrows, 4ArrowsGray, 4RedToBlack, 4Rating, 4TrafficLights, 5Arrows, 5ArrowsGray, 5Rating, 5Quarters; reverse 反转图标顺序, showValue 是否显示数值, points 的个数等于图标数 (默认按百分比均分, 三个图标为 0, 33, 67). 阈值的 gte (默认 true) 表示图标从该值本身 (>=) 开始, 为 false 时从大于它 (>) 开始.

阈值写作 'min', 'max' 或 { type, value }, type 为 'num', 'percent', 'percentile' 或 'formula'.

ValidationRule#

数据有效性规则. 各类型:

  • list: 下拉列表. values 为字符串数组 (合计至多 255 个字符), 或 formula 为来源范围 (如 'Sheet2!$A$1:$A$9'); showDropdown (默认 true) 是否显示下拉箭头.
  • whole, decimal, date, time, textLength: 整数, 小数, 日期, 时间与文本长度. operator 同 cellIs (默认 'between'); between 与 notBetween 用 min 与 max, eq 与 ne 用 value, gt 与 ge 用 min, lt 与 le 用 max (单个操作数时也可写 value). date 接受 'yyyy-mm-dd' 与序列号, 读回为 'yyyy-mm-dd'; time 接受 'HH:mm', 'HH:mm:ss' 与一天中的小数, 读回为 'HH:mm:ss'.
  • custom: formula 为自定义公式.
  • any: 任何值, 只用于显示输入提示.

公共键:

  • [ allowBlank = true ] { boolean } - 是否允许空值
  • [ prompt ] { { title?: string; text?: string }} - 选中单元格时的输入提示, 默认关闭
  • [ error ] { { title?: string; text?: string; style?: string }} - 输入无效时的提示, 默认开启. style 为 'stop' (默认), 'warning' 或 'info'

prompt 与 error 给 false 表示关闭, 读回时关闭的一项为 false. 标题至多 32 个字符, 输入提示至多 255 个字符, 错误提示至多 225 个字符. 公式在改动前先解析, 文件格式存不下的公式失败于 INVALID_ARGUMENT.

let wb = xlsx.open('./report.xlsx');
try {
    let sheet = wb.sheet(1);
    sheet.addConditionalFormat('D2:D100', { type: 'cellIs', operator: 'gt', value: 20, style: { font: { color: '#C00000', bold: true } } });
    sheet.addConditionalFormat('B2:B100', { type: 'dataBar', color: '#5B9BD5' });
    sheet.addValidation('B2:B100', { type: 'whole', operator: 'between', min: 0, max: 999, error: { title: '数量', text: '请输入 0 至 999 的整数' } });
    sheet.addValidation('E2:E100', { type: 'list', values: ['待发货', '已发货', '已签收'] });
    sheet.validations().forEach(v => console.log(v.range, v.rule.type));
    wb.save();
} finally {
    wb.close();
}

选项#

OpenOptions#

打开表格文件的选项, 用于 info, sheetNames, read, readAll 与 open.

  • [ password ] { string } - 加密文件的密码, 见 加密与密码
  • [ format ] { 'xlsx' | 'xlsm' | 'xls' | 'csv' | 'tsv' } - 扩展名无法判断格式时指定
  • [ mode = 'auto' ] { 'auto' | 'full' | 'stream' } - 载入方式, 见 读取模式与大表. info 与 sheetNames 不接受此键
  • [ encoding ] { string } - csv 的编码, 默认自动探测, 见 csv 与编码
  • [ delimiter ] { string } - csv 的分隔符 (一个字符), 默认自动探测
  • [ parseNumbers = true ] { boolean } - csv 中形如数字的字段转为数字
  • [ parseBooleans = false ] { boolean } - csv 中的 true / false 转为布尔值

ReadOptions#

读取行的选项, 用于 read, readAll 与 Sheet#read. read 与 readAll 同时接受 OpenOptions 的键.

  • [ sheet ] { string | number } - 工作表名称或从 1 计的序号, 默认第一个可见的工作表. 只用于 read
  • [ range ] { string } - 读取的 A1 范围, 默认为工作表的已用范围
  • [ from ] { number } - 第一个数据行的工作表行号
  • [ to ] { number } - 最后一个数据行的工作表行号
  • [ header = false ] { boolean } - 范围的第一行作为表头, 其余各行返回对象
  • [ cells = false ] { boolean } - 各单元格返回 CellDetail
  • [ formatted = false ] { boolean } - 各单元格返回显示文本
  • [ blankRows ] { boolean } - 是否返回空行, 数组行默认 true, 对象行默认 false
  • [ trim = false ] { boolean } - 去掉字符串值与表头名的首尾空白
  • [ limit ] { number } - 至多返回的行数, 0 返回空数组

说明:

  • header: true 时表头总是范围的第一行, from 与 to 只限制其后的数据行.
  • 空行指没有任何值的行. 返回的空行止于最后一个有数据的行; 给出 range 时, 范围开头的空行同样返回.
  • cells 与 formatted 不能同时为 true, 否则失败于 INVALID_ARGUMENT.
  • 流式读取且文件没有记录已用范围时 (部分程序生成的 xlsx, 以及流式读取的 csv), 每行按自身的宽度从 A 列返回, 各行长度可能不同.

WriteOptions#

写入的选项, 用于 write 与 writeAll. 带 * 的键也用于 append.

  • [ sheet ] { string } - 工作表名称, 默认 'Sheet1'. 只用于 write *
  • [ header ] { boolean | string[] } - 表头, 见下文 *
  • [ format ] { 'xlsx' | 'xls' | 'csv' | 'tsv' } - 目标格式, 默认按目标的扩展名. 不能新建 xlsm (失败于 UNSUPPORTED)
  • [ dateFormat = 'yyyy-mm-dd hh:mm:ss' ] { string } - 写入日期使用的数字格式 *
  • [ formulas = false ] { boolean } - 以 = 开头的字符串按公式写入 *

  • 输出为 csv 或 tsv 时为带 BOM 的 UTF-8. 输出为 xlsm 时失败于 UNSUPPORTED (值中没有宏).

  • passwords 按输入顺序给出各输入的密码, 项数必须等于输入个数, '' 或 null 表示该输入没有密码.

6.8.1

整载的单元格数 1,000,000 个, 另受插件剩余 Java 堆的 90% 限制
空闲的工作簿与写出器 30 分钟没有调用且没有进行中的操作时被关闭
单行大小 32 MiB
选项对象 序列化后 64 KiB
merge 的输入 2 到 64 个
split 的输出 256 个
Sheet#find 的结果 默认 100 个, 至多 1000 个
工作表名称 31 个字符
xlsx / xlsm 的行列 1,048,576 行, 16,384 列 (XFD)
xls 的行列 65,536 行, 256 列 (IV)
查看器显示等待 60 秒
进度回调间隔 至少 100 毫秒
调用超时 无

读取并筛选#

let rows = xlsx.read('./sales.xlsx', { header: true, trim: true });
let big = rows.filter(r => r['金额'] >= 1000);
console.log('大额订单 ' + big.length + ' 笔');
big.forEach(r => console.log(r['客户'], r['金额']));

});
console.log(r.path);

流式写出与读取大表#

let w = xlsx.createWriter('./big.xlsx', { header: ['序号', '值'] });
try {
    for (let i = 1; i <= 300000; i++) {
        w.addRow([i, i * 2]);
    }
    w.close();
} catch (e) {
    w.abort();
    throw e;
}
let wb = xlsx.open('./big.xlsx', { mode: 'stream' });
try {
    let sum = 0;
    wb.sheet(1).eachRow((rows, startRow) => {
        rows.forEach(row => { sum += row[1]; });
    }, { from: 2 });
    console.log(sum);
} finally {
    wb.close();
}

异步与取消#

let job = xlsx.convertAsync('./big.xlsx', './big.csv', {
    onProgress: p => console.log(p.stage, p.percent),
});
let timer = setTimeout(() => job.cancel(), 10000);
job.then(r => {
    clearTimeout(timer);
    console.log('完成: ' + r.path);
}).catch(e => {
    clearTimeout(timer);
    console.error(e.code === 'CANCELLED' ? '已取消' : e.toString());
});
