应用设置 (Settings)#

运行时支持 Rhino Node.js 主线程 Node.js Worker Bun
入口 settings autojs6:settings autojs6:settings host.settings
状态 已支持 4 项 已支持 4 项 已支持 4 项 需授权 4 项
授权 - - - settings.control 4 项

各 API 在同一运行时中的入口, 状态与授权一致, 没有差异项.

Node.js 与 Bun 的导入方式, 异步返回值与授权检查见 运行时 API.

settings 模块用于读取和修改 AutoJs6 的布尔型偏好设置, 以及将 AutoJs6 设置导出为设置归档.

settings 与 $settings 指向同一个模块对象.

此模块不是 android.provider.Settings 的别名.

settings

[m] isEnabled#

isEnabled(key)#

6.8.0

  • key { string } - 设置键或兼容别名
  • returns { boolean } - 设置是否已启用

读取指定布尔型偏好设置.

foreground_service 的返回值是保存的开关设置, 不是服务实时存活状态或 Android 17 while-in-use 能力查询.

当设置不存在时返回 false.

console.log(settings.isEnabled('foreground_service'));

[m] setEnabled#

setEnabled(key, enabled)#

6.8.0

  • key { string } - 设置键或兼容别名
  • enabled { boolean } - 是否启用设置
  • returns { void }

写入指定布尔型偏好设置.

写入 foreground_service 本身不直接启动或停止 Android 服务. 需要恢复 Android 17 后台音频 时, 在应用界面操作前台服务开关, 不要将 settings.setEnabled('foreground_service', true) 当作获取后台播放资格的方法.

let previous = settings.isEnabled('stable_mode');
settings.setEnabled('stable_mode', !previous);

[m] export#

export(path?, categories?)#

6.8.0 Non-UI

  • [ path ] { string } - 归档文件或文件夹的路径, 相对路径按脚本工作目录解析 (与 files.path 相同); 省略时写入 AutoJs6 工作路径下的 backups/settings/ 文件夹
  • [ categories ] { string | string[] } - 分类 id 或分类 id 数组, 可由 categories 获取, 插件分类为 plugin:<包名>; 省略时为导出向导默认勾选的分类 (不含插件)
  • returns {{
    • path: string - 写入的归档文件的绝对路径;
    • categories: string[] - 写入归档的分类 id, 设置与数据分类按设置页顺序排列, 插件分类按包名排在其后;
    • entries: number - 写入的条目总数;
    • unexportable: number - 无法写入归档而被略去的设置值数量;
    • skipped: {{ id: string; reason: 'sensitive' | 'empty' | 'unavailable' }}[] - 请求了但未写入的分类及原因;
  • }} - 导出结果

将 AutoJs6 设置导出为设置归档 (zip 文件). 归档格式与 设置 > 配置 > "管理 AutoJs6 设置" > "导出设置" 向导导出的文件相同, 可在同一页面的 "导入设置" 中导入.

path 以 / 结尾或为已存在的文件夹时, 归档写入该文件夹, 文件名为 autojs6-settings-<yyyyMMdd-HHmmss>.zip. 同一秒已有同名文件时依次追加 -1, -2 等, 不会替换已有文件. 省略 path 时同样如此. 其他路径即归档文件本身 (不会自动追加 .zip), 文件已存在时被替换. 缺少的父文件夹会被创建. 归档先写入同一文件夹中的临时文件, 写入失败时不会留下不完整的归档.

categories 中的分类按设置页顺序写入, 重复的 id 只写入一次. 默认分类为 categories 中 defaultSelected 为 true 的分类, 与导出向导首次打开时的勾选相同, 包含快捷方式与颜色库两个数据分类.

脚本不能导出凭据. 请求 credentials 分类时, 该分类不会写入, 并以 reason: 'sensitive' 记入 skipped. 数据分类没有可导出的内容时 (例如没有快捷方式), 该分类不会写入, 并以 reason: 'empty' 记入 skipped.

从 AutoJs6 6.8.1 起, 插件分类 plugin:<包名> 导出该官方插件的设置, 与导出向导中勾选该插件的结果相同, 导入设置时交由插件自身导入. 只有明确请求的插件才会导出. 插件声明其设置含敏感内容时, 脚本同样不能导出, 该插件以 reason: 'sensitive' 记入 skipped. 插件未安装, 未启用, 不是官方插件, 不支持设置迁移或导出失败 (例如 10 秒内未响应) 时, 以 reason: 'unavailable' 记入 skipped. 请求的插件全部被略去时仍会写入归档.

以下情况抛出异常, 且不会写入任何文件:

  • path 不是字符串, 或为空白字符串
  • categories 不是字符串或字符串数组, 或为空数组
  • categories 含未知的分类 id (插件分类须为 plugin:<包名> 形式), 或只请求了 credentials
  • 在 UI 线程中调用

归档超过 16 MB 或写入失败时同样抛出异常.

let result = settings.export();
console.log(result.path);
console.log(`${result.categories.length} 个分类, ${result.entries} 项`);

let result = settings.export('./exports/', [ 'appearance', 'general', 'credentials' ]);
result.skipped.forEach(s => console.log(`${s.id}: ${s.reason}`)); // 打印 "credentials: sensitive".

// 导出外观设置与全部可用且不含敏感内容的插件设置.
let plugins = settings.categories().filter(c => c.kind === 'plugin' && c.available && !c.sensitive);
let result = settings.export(null, [ 'appearance' ].concat(plugins.map(c => c.id)));
console.log(result.categories.join(', '));

[m] categories#

categories()#

6.8.0 Non-UI

  • returns {{
    • id: string - 分类 id, 可用于 export 的 categories 参数; 插件分类为 plugin:<包名>;
    • title: string - 分类名称, 随应用语言变化; 插件分类为插件名称;
    • kind: 'settings' | 'data' | 'plugin' - 种类, 分别为设置分类, 数据分类 (快捷方式, 颜色库) 与插件分类;
    • label: string - 插件名称, 仅插件分类有此属性;
    • entries: number - 当前可导出的条目数;
    • defaultSelected: boolean - 是否属于 export 的默认分类, 插件分类总是 false;
    • sensitive: boolean - 是否为敏感分类 (凭据, 或声明设置含敏感内容的插件), 敏感分类不能由脚本导出;
    • available: boolean - 插件当前能否导出设置, 仅插件分类有此属性;
    • reason: 'timeout' | 'denied' | 'busy' | 'failed' - 插件不能导出的原因, 分别为 10 秒内未响应, 插件拒绝调用, 插件正忙与其他失败, 仅 available 为 false 的插件分类有此属性;
  • }}[] - 分类信息数组

获取全部设置分类, 按设置页顺序排列, 与导出向导的分类列表相同. 从 AutoJs6 6.8.1 起, 设置分类之后按包名列出每个已发现的官方插件 (已安装, 已启用且支持设置迁移) 各一项. 插件不能导出时, 其 entries 为 0, sensitive 为 false.

统计条目数需要读取设置与数据, 并调用每个插件 (每个插件最多等待 10 秒), 因此不能在 UI 线程中调用.

settings.categories()
    .filter(c => c.entries > 0 && !c.sensitive)
    .forEach(c => console.log(`${c.id} (${c.kind}): ${c.title}, ${c.entries} 项`));

插件设置迁移#

6.8.1

自 AutoJs6 6.8.1 起, 设置 > 配置 > "管理 AutoJs6 设置" 的导出与导入同样迁移官方插件的设置. 插件同时满足以下条件时参与迁移, 不满足的插件不会被调用:

  • 插件为官方插件, 且已在插件中心启用
  • 插件声明支持设置迁移 (参阅 插件接入)

插件的设置保存在设置归档的 plugins/<包名>/settings.json 中 (含敏感内容时加密保存, 参阅 敏感设置). AutoJs6 不修改插件给出的内容, 导入时交还插件自身导入. 各操作对插件设置的处理如下:

操作 插件设置
导出向导 在应用设置分类之后的 "官方插件" 分组中列出, 显示条目数. 默认勾选, 含敏感内容的插件除外. 插件 10 秒内未响应或调用失败时显示为不可用, 不能勾选
settings.export 只导出 categories 中明确请求的 plugin:<包名>, 不导出含敏感内容的插件
周期备份 包含全部参与迁移的插件, 含敏感内容的插件除外
导入前的备份 包含参与迁移的插件, 供 "撤销上次导入" 恢复插件原有的设置. 导入过程中经插件中心安装或启用的插件不在其中
修改设置, 导入, 重置或撤销后的自动备份 不包含插件

导入的归档含有本机未安装或未启用的插件时, 导入向导为其增加 "安装插件" 或 "启用插件" 一项, 经插件中心安装或启用后继续导入该插件的设置; 未安装或未启用即返回时, 该插件的设置不导入. 结果页按插件列出写入与跳过的条目数. 插件表示部分设置需要重启插件后生效时, 结果页给出提示; AutoJs6 不会重启插件, 由插件自行处理. AutoJs6 6.8.0 导入此类归档时略过插件设置, 其余分类照常导入.

敏感设置#

插件导出的设置含有令牌, 密码, API 密钥或配对密钥等机密时, 应将其标记为敏感 (sensitive). 对于敏感的插件设置, AutoJs6:

  • 在归档中与 "凭据与授权" 分类一样加密保存: 使用本机密钥加密, 导出时设置了 "插件密钥密码" 则同时用该密码加密. 未设置密码时只能在导出它的设备上的 AutoJs6 中导入; 设置了密码时, 在其他设备上输入该密码即可导入
  • 在导出向导中默认不勾选, 勾选时显示与 "凭据与授权" 分类相同的警告
  • 不允许脚本导出: settings.categories 中其 sensitive 为 true, settings.export 将其以 reason: 'sensitive' 记入 skipped
  • 不写入周期备份

插件也可以不导出机密并标记为不敏感, 此时设置以未加密的 JSON 保存.

插件接入#

本节面向官方插件的开发者. 插件经 Android ContentProvider 的 call 方法与 AutoJs6 交换设置, 完整的契约 (请求与结果的键, 文档格式, 错误码, 版本规则与大小上限) 参阅 插件设置迁移协议 V1.

添加插件开发库 common-plugin-api 1.1.0 或以上版本:

dependencies {
    implementation("io.github.supermonster003:autojs6-common-plugin-api:1.1.0")
}

继承 PluginSettingsTransferProvider 并实现导出与导入. 设置保存在 SharedPreferences 中时, 可直接使用 SharedPreferencesSettingsTransfer:

import android.content.Context
import org.autojs.plugin.common.api.PluginSettingsTransferProvider
import org.autojs.plugin.common.api.SharedPreferencesSettingsTransfer
import org.autojs.plugin.common.api.SharedPreferencesSettingsTransfer.Key
import org.json.JSONObject

class SettingsTransferProvider : PluginSettingsTransferProvider() {

    private val transfer by lazy {
        val preferences = requireNotNull(context).getSharedPreferences("settings", Context.MODE_PRIVATE)
        SharedPreferencesSettingsTransfer(
            SharedPreferencesSettingsTransfer.Store(
                name = "settings",
                preferences = preferences,
                keys = listOf(Key.string("key_sample_mode"), Key.int("key_sample_limit"), Key.string("key_sample_token")),
                sensitiveKeys = setOf("key_sample_token"),
            ),
        )
    }

    override fun exportSettings(request: Request) = transfer.exportSettings()

    override fun importSettings(settings: JSONObject, source: Source, request: Request) = transfer.importSettings(settings)
}

在 AndroidManifest.xml 的 application 中声明 provider 与协议版本. provider 的授权名必须为 <包名>.autojs6.settings, 并受 org.autojs.permission.PLUGIN 权限保护:

<application>
    <provider
        android:name=".SettingsTransferProvider"
        android:authorities="${applicationId}.autojs6.settings"
        android:exported="true"
        android:permission="org.autojs.permission.PLUGIN" />
    <meta-data
        android:name="org.autojs.plugin.contract.SETTINGS_TRANSFER"
        android:value="1" />
</application>

PluginSettingsTransferProvider 在调用插件的实现之前检查调用方: 调用方须持有 org.autojs.permission.PLUGIN 权限, 否则抛出 SecurityException (provider 的 android:permission 属性不约束 call). 它还检查协议版本与 256 KiB 的文档大小上限, 并将异常转换为契约的错误码. 两个方法在插件的 Binder 线程中执行, 须在 10 秒内返回, 且不能显示界面.

  • exportSettings(request) 返回 Exported(settings, entries, sensitive). settings 为设置的 JSON 对象, entries 为导出向导中显示的条目数, sensitive 参阅 敏感设置. 只导出用户选择的设置, 不包含缓存, 本机记录, 下载的文件, 模型与历史记录. request.purpose 为 export (导出) 或 backup (备份), 两者应返回相同的内容.
  • importSettings(settings, source, request) 返回 Imported(written, skipped, restartNeeded). 导入应当宽松: 只写入认识且有效的条目, 其余计入 skipped; 文档未提及的设置保持原值; 一次写入全部条目, 同一文档重复导入的结果相同. source 提供导出该文档的插件版本 (versionCode, versionName), 用于迁移旧版本的设置. 部分设置需要重启插件后生效时, 将 restartNeeded 设为 true.
  • 自 common-plugin-api 1.1.1 起, 导入时 request.purpose 为 import (导入归档) 或 undo ("撤销上次导入", 交还的是本机在那次导入之前的备份), request.isUndo 在后者时为 true; AutoJs6 6.8.0 不传该值, 视为 import. 只允许在本机设置的条目 (例如用户在本机授予的权限) 可在导入归档时跳过, 在撤销时接受. 使用 1.1.0 的插件不区分两者.
  • 覆写 restartProcessAfterImport 为 true 时 (默认为 false), 导入结果的 restartNeeded 为 true 时插件进程在返回结果约 500 毫秒后退出, 插件有界面在前台时不退出; 下次调用或绑定时插件重新启动.
  • 抛出 PluginSettingsTransferException 可返回指定的错误码, 例如插件正在迁移自身数据时返回 BUSY, 导出向导将该插件显示为正忙.

SharedPreferencesSettingsTransfer 由一个或多个 Store 构成, 每个 Store 对应一个 SharedPreferences 文件, 列出参与迁移的键及其类型 (Key.bool, Key.int, Key.long, Key.float, Key.string, Key.stringSet 与 Key.json). 导出只写出有值且类型相符的键; 导入跳过未知的文件与键, 类型不符或无效的值, 每个文件只提交一次. sensitiveKeys 中的键有值时, 导出的设置标记为敏感.

AutoJs6 6.8.0 及更早的版本不会调用该 provider, 因此支持设置迁移不需要提高插件要求的 AutoJs6 最低版本.
