从 6.7 升级到 6.8 (Upgrade to 6.8)#

自 AutoJs6 6.8.0 起, OCR, 条码识别, OpenCV, OpenCC, 拼音, 脚本库, 离线文档等过去内置的功能改由独立安装的官方插件提供. 在 6.7 上正常运行的脚本, 升级后报 "缺少依赖插件" 一类错误时, 多数只需要安装对应的插件, 不需要修改代码.

本页面不是脚本 API. 本页列出需要安装哪个插件, 常见报错的含义, 插件安装失败时的处理办法, 以及 AutoJs6 安装包怎么选.

快速处理#

  • 脚本运行时弹出 "需要安装插件" 对话框 (AutoJs6 6.8.1 起): 点 "去安装" 打开插件安装向导, 脚本缺少的插件已预先选中. 点 "本次不再提示" 后, 到 AutoJs6 重新启动之前, 这些插件缺失时不再弹出对话框. 同一次运行只弹出一次, 对话框打开期间发现的其他缺失插件会并入其中.
  • 脚本在后台运行 (没有打开的 AutoJs6 界面) 时, 改为发送一条通知, 同时在日志页打印一行带 "去安装" 链接的提示. 点按通知或 "去安装" 都会打开插件安装向导, 缺少的插件已预先选中.
  • 也可以直接用插件安装向导按分类勾选并批量安装官方插件, 入口: 设置向导, 主页插件标签页的悬浮按钮菜单, 或插件中心的 "+" 菜单 > "插件安装向导".
  • 插件中心的入口为主页抽屉 > "插件中心". 插件中心与插件安装向导的菜单中都有 "从 6.7 升级到 6.8", 用于打开本页.

官方插件安装后默认启用. 插件在插件中心被关闭, 或未获授权时, 功能同样不可用, 需要在插件中心重新启用或授权.

常见报错与对应插件#

报错的文字随 AutoJs6 的语言变化, 下表的示例为简体中文界面下的文字, 其中带引号的名称为缺少的插件.

报错 (示例) 原因 做法
缺少依赖插件: "OpenCV", 可在 AutoJs6 "插件中心" 搜索并在线安装相关的官方插件 未安装 OpenCV 插件 安装 OpenCV 插件
缺少 "ML Kit Barcode plugin" 所需的插件. 请先安装插件, 然后重试. 未安装提供该模块的插件 按 功能与插件对照 安装对应插件
插件 "..." 已在插件中心关闭 (AutoJs6 6.8.1 起), 插件 "..." 未在插件中心启用 (AutoJs6 6.8.0) 插件已安装, 但在插件中心被关闭 在插件中心启用该插件
插件 "..." 未在插件中心获得授权 插件已安装, 但未获授权 在插件中心授权该插件
当前插件需要更高版本的 AutoJs6 宿主环境 (要求 versionCode: ..., 当前 versionCode: ...), 需要升级 AutoJs6. 已安装的插件比 AutoJs6 新 升级 AutoJs6
Cannot find module 'dayjs': it is provided by the official plugin "Bundled Libraries", which is not installed. Install the plugin in AutoJs6 > Plugin center. require 的库或读取的全局对象由 Bundled Libraries 提供, 插件不可用 安装或启用 Bundled Libraries, 错误的 code 为 MODULE_NOT_FOUND, reason 的含义参阅 插件不可用时

脚本用 try...catch 自己捕获的插件错误不会弹出 "需要安装插件" 对话框, 需要根据错误消息自行处理.

不需要插件的行为变化#

以下变化与插件无关, 依赖旧行为的脚本可能需要调整:

  • Rhino 引擎的 Promise 及部分语法行为改为与 ECMAScript 规范一致, 例如 Promise 回调改为微任务执行, 为 const 变量重新赋值时抛出 TypeError.
  • console 控件及控制台浮动窗口改为显示当前脚本的日志, 全局日志通过 globalconsole 控件或日志页面查看.
  • 打包应用的目标 SDK 版本由 29 调整为 37, 共享存储及本地网络访问需要按系统要求授权.

完整的变化列表参阅 AutoJs6 的 发行历史.

插件安装失败怎么办#

以下说明适用于 AutoJs6 6.8.1 及以上版本. 下载或安装失败的对话框会写明错误与原因, 处理前先查看其中的说明.

插件列表为空或插件索引加载失败#

插件列表来自 GitHub 上的插件索引. AutoJs6 先从 raw.githubusercontent.com 读取, 失败时自动改用 cdn.jsdelivr.net 与 fastly.jsdelivr.net. 全部失败时, 插件中心与插件安装向导列出已尝试的域名与各自的错误 (如 "域名无法解析", "连接超时", "安全连接 (TLS) 失败"), 并继续显示上次成功加载的列表.

做法: 检查网络连接与代理设置后重新打开或刷新列表. 只有某个域名失败时, 列表仍可正常加载.

插件下载失败#

下载失败时 AutoJs6 自动重试 2 次. 仍然失败时, 对话框显示错误, 域名, HTTP 状态与已下载的大小, 并在 "其他下载方式" 中提供:

  • "复制下载链接": 复制插件安装包的下载地址, 在其他设备或网络下载后传到本机安装.
  • "用浏览器下载": 用浏览器下载安装包, 下载完成后在浏览器或文件管理器中打开安装包即可安装.
  • "用系统下载管理器下载": 由系统下载管理器下载, 完成后自动继续安装.

插件安装向导批量安装时, 安装结束后的汇总列出下载失败的插件, 其中的 "其他下载方式" 同样提供以上三种方式 (失败的插件有多个时先选择其中一个).

手动下载的安装包也可以在插件中心的 "+" 菜单 > 从 "本地文件" 安装.

安装包检查未通过#

AutoJs6 在安装前检查下载的安装包, 检查未通过时不开始安装, 对话框说明具体原因:

原因 做法
文件大小与索引不符, 或不是有效的安装包 下载不完整或文件已被替换, 重新下载, 必要时换用其他下载方式
包名或版本号 (versionCode) 与索引不符 下载到的不是所选的插件或版本, 重新下载; 仍不符时可能是索引尚未更新, 稍后再试
签名与已安装的版本不同 需要先卸载已安装的版本再安装, 卸载会清除该插件的数据
版本低于已安装的版本 Android 不允许直接降级安装, 需要先卸载已安装的版本
需要更高的 Android 版本 该插件不支持本设备的 Android 版本
只支持其他 CPU 架构 (ABI) 改选 universal 或与本设备 ABI 一致的插件变体
存储空间不足 清理存储空间后重试

安装被系统阻止或取消#

  • 首次安装时, 系统可能要求允许 AutoJs6 安装未知应用, 按系统提示允许后重试.
  • "安装被设备策略或用户限制阻止": 设备的管理策略或系统设置禁止安装应用, 需要在系统设置中解除限制.
  • 安装 APKS / XAPK 等分包安装包需要 3-Setup Installer 插件. 具备 Shizuku, Root 或 Dhizuku 授权时, 插件安装向导可以通过该插件静默安装.

插件中心显示 "[ 旧 SDK 插件 ]"#

这是本机已安装, 但任何插件索引都未收录的旧版 SDK 插件, 例如为其他 Auto.js 版本开发的插件. AutoJs6 6.8 的 ocr 等模块不使用这类插件, 需要相应的功能时, 请安装 功能与插件对照 中的官方插件.

AutoJs6 安装包怎么选#

每个版本的 发行页面 提供 5 个 APK, 功能相同, 区别只在于文件名中的 ABI (内置原生库适用的 CPU 架构):

  • arm64-v8a: 64 位 ARM 设备, 即近年的绝大多数手机与平板.
  • armeabi-v7a: 32 位 ARM 设备, 多为较旧的手机, 或只运行 32 位应用的系统.
  • x86_64 / x86: x86 架构的设备, 主要是电脑上的 Android 模拟器 (x86_64 为 64 位, x86 为 32 位).
  • universal: 包含以上全部 ABI, 可安装在任何设备上, 体积只略大于单一 ABI 版本 (以 6.8.0 为例约多 1.2 MB).

不确定下载哪个时, 选择文件名含 universal 的 APK. 各 APK 签名与版本号相同, 之后可以互相覆盖安装. 从 6.7 升级时直接覆盖安装, 已有的脚本与设置会保留.

部分插件同样按 ABI 拆分发布. 插件支持的 ABI 与本设备不符时, 插件中心在下载前给出提示.
