3-Probe Debugger#

3-Probe Debugger 是 AutoJs6 的官方远程调试插件 (AutoJs6-Plugin-Three-Probe-Debugger). 它在设备上运行 Debug Adapter Protocol (DAP) 服务, 让电脑上的 VS Code, JetBrains IDE, Neovim 等 DAP 客户端调试设备上的 AutoJs6 脚本: 断点, 单步执行, 调用栈, 变量, 监视与调试控制台. 支持 Rhino JavaScript, TypeScript (按源映射在 .ts 源码上断点) 与 Node.js 脚本. 本页面自 AutoJs6 6.8.1 与 3-Probe Debugger 1.0.0 起适用.

本页面介绍插件本身. 在电脑上调试脚本的步骤与调试配置见 调试脚本 (Debug Scripts); 脚本得知自身是否正被调试的 API 见 调试 (Debugging).

安装与启用#

  1. 在插件中心的官方插件库安装 3-Probe Debugger, 或从 GitHub Releases 下载安装包. 插件为适用于全部设备的单个安装包, 需要 Android 7.0 (API 24) 或更高版本.
  2. 插件需要 AutoJs6 6.8.1 (内部版本 6641) 或更高版本. 较旧的 AutoJs6 在插件中心把它显示为不兼容.
  3. 插件安装后在插件中心默认不启用, 需要在插件中心启用它.
  4. 在 AutoJs6 主页抽屉中打开 "调试服务" 开关. 插件未安装, 未启用或尚未被 Android 激活时, 开关会给出提示 (例如 "在 AutoJs6 中启用 3-Probe Debugger 插件并开启调试服务?"), 按提示操作即可.
  5. 开发连接 (客户端模式或服务端模式) 的管理对话框中有 "随开发连接自动开启调试服务" 选项: 打开后, 建立开发连接时自动开启调试服务, 除非你曾手动停止它. 该选项只在已安装并启用 3-Probe Debugger 时生效.

抽屉中 "调试服务" 一项显示服务的状态, 其 "设置" 按钮打开插件的设置页:

状态 含义与处理
运行中, 端口 8347 DAP 服务正在监听, 调试客户端可以连接
未安装插件 通过插件安装向导安装 3-Probe Debugger 并启用
插件已禁用 在插件中心启用插件
需要授权 插件需要先在插件中心获得授权
需要激活 插件已安装但尚未被 Android 激活, 按提示激活
已被强行停止, 需要激活 开关开启期间插件被系统强行停止且暂时无法自动恢复, 见下文 被系统强行停止
版本不兼容 AutoJs6 与插件的版本不匹配, 安装兼容的版本
等待 AutoJs6 连接 AutoJs6 曾退出或被系统结束; 监听保持开启, AutoJs6 再次启动并打开调试服务后自动恢复, 见 常见问题
启动失败 监听未能启动 (例如端口被其他应用占用), 在插件设置中修改端口后重试

只有在调试服务开启之后开始运行的 Rhino 脚本才能被调试器附加, 见 可附加的条件. AutoJs6 打包生成的应用不能被调试.

插件的警告#

调试服务运行期间, 插件发现可能影响调试的情况时会告知 AutoJs6. 警告显示在 "调试服务" 一项的状态下方, 并以 toast 提示一次 (同一警告在 AutoJs6 本次运行期间只提示一次, 监听重新启动后仍显示, 但不再提示):

警告 含义与处理
后台活动受限 Android 限制了插件的后台活动 (例如 HyperOS 对新安装应用的默认设置), 熄屏或插件在后台时监听可能被停止. 点按 "调试服务" 一项, 说明对话框中的 "打开 "设置"" 打开插件的应用信息页, 在其中允许后台运行 (例如把电池用量或省电策略设为 "不受限制" / "无限制"). 解除限制后回到 AutoJs6, 警告不再显示. 插件只在监听启动时检查这一限制; 限制在之后才生效时 (例如 HyperOS 在新安装的插件离开屏幕约 1 分钟后才限制它), AutoJs6 回到前台时会自行读取并显示该警告
前台服务未能启动 插件未能启动保持监听运行的前台服务, Android 回收插件进程时监听随之停止. 处理方法同上
Node.js 中继无法监听端口 Node.js 中继端口被占用, 只能调试 Rhino 脚本; 在插件设置中更换 Node.js 中继端口

局域网中的电脑多次尝试失败而被暂时拦截时, AutoJs6 只以 toast 提示一次. 插件发来的其他警告按原文 (英文) 显示. 监听停止或重新启动时警告清除, 重新启动后仍存在的情况会再次报告.

被系统强行停止#

部分系统在清理最近任务或后台应用时会强行停止插件 (例如 ColorOS). 开关开启期间插件被强行停止时, AutoJs6 自动唤醒插件并重新连接. 插件连续被停止时, 两次自动恢复之间的间隔逐次拉长 (第一次之后 1 分钟, 最长 30 分钟); AutoJs6 在后台且没有 "显示在其他应用上层" 权限时无法唤醒插件, 回到 AutoJs6 时再恢复.

暂时无法恢复时, "调试服务" 一项显示 "已被强行停止, 需要激活", 开关保持开启的意图 (下次打开 AutoJs6 主界面时再次尝试). 点按开关会说明原因: "激活" 立即唤醒插件并开启调试服务, "打开 "设置"" 打开插件的应用信息页, 在其中允许自启动与后台运行. 插件首页 "保持运行" 一栏按 HyperOS / MIUI, ColorOS / OxygenOS 与其他系统说明需要的设置. 在 AutoJs6 中手动关闭的开关不会被自动恢复.

插件界面#

从桌面图标或插件中心的 "打开插件" 进入插件界面.

  • 状态页: 调试服务是否在运行, 没有运行时该怎么做, 端口, 监听范围与允许连接的范围, 连接方式 (本机地址, 局域网地址及其二维码, 可复制的 adb forward 命令, VS Code, JetBrains IDE 与其他 DAP 客户端的简要说明), 以及打开的调试会话 (编辑器, 脚本, 暂停的线程, 每个线程都有 "继续" 按钮).
    • 局域网中的电脑请求连接时, 最上方显示待确认的卡片 (编辑器, 地址, 倒计时与三个回答按钮), 通知没有出现时可在这里回答, 见 安全.
    • 系统限制插件的后台活动时, 置顶显示 "后台活动受限" 提示与打开应用信息的按钮.
    • 折叠的 "保持运行" 一栏按 HyperOS / MIUI, ColorOS / OxygenOS 与其他系统说明电池与自启动设置, 附打开应用信息的按钮. ColorOS 与 OxygenOS 还要在 设置 > 应用 > 自动启动 中打开 3-Probe Debugger 与 AutoJs6, 这张列表与应用信息里的开关是分开的.
  • 已配对的电脑: 在手机上选择过 "允许并记住" 的电脑, 可以撤销, 见 安全.
  • 设置: DAP 端口 (默认 8347), Node.js 中继端口 (默认 8348), 监听范围, 令牌模式与令牌, 通知, 外观 (语言, 夜间模式, 主题色, 启动器图标, 默认跟随 AutoJs6), 发行历史与更新检查. 修改端口, 监听范围或令牌模式后, 运行中的监听立即按新设置重启, 打开的调试会话随之结束. 把监听范围从 "仅本机" 改为局域网时, 插件检查通知: 通知未开启时说明询问不会弹出, 只能在首页回答, 并请求通知权限; "连接请求" 类通知被关闭时给出 "打开通知设置" 入口.
  • 通知: 监听运行期间显示前台服务通知 (监听的端点与会话数); 局域网中的电脑请求连接时显示确认通知, 熄屏时亮屏并显示全屏确认页; 脚本暂停时显示 "脚本已暂停于 文件:行" 通知并带 "继续" 按钮, UI 线程暂停时还显示距自动继续的倒计时. Android 13 及以上未授予通知权限时, 状态页会提示授予; Android 14 及以上设置页的 "通知" 一节另有 "全屏询问" 一行, 未允许时点按即可打开系统设置.

连接方式#

方式 电脑怎样到达手机 监听范围 手机确认
ADB 转发 数据线与 adb forward tcp:8347 tcp:8347, 客户端连接 127.0.0.1:8347 仅本机 (默认) 不需要
局域网直连 客户端连接 <手机地址>:8347 (地址见状态页) 局域网 (所有网络接口) 新电脑第一次连接时需要
开发连接隧道 DAP 消息经 AutoJs6 已有的开发连接 (端口 6347 / 7347) 传递, 不另开端口, 不需要 adb forward 仅本机即可 不需要, 沿用开发连接已有的信任
  • ADB 转发: 调试 Node.js 脚本时还要转发中继端口: adb forward tcp:8348 tcp:8348. 状态页 "数据线 (adb forward)" 一项给出可复制的命令.
  • 局域网直连: 在插件设置中把 "监听范围" 改为 "局域网 (所有网络接口)". 同一网络中的电脑可直接连接, 新电脑开始调试之前手机会先询问, 见 安全.
  • 开发连接隧道: 目前由 AutoJs6 VSCode 扩展 1.3.0 及以上版本使用 (调试配置的 transport 为 auto 或 tunnel). 隧道下不能为子脚本开独立会话 (childSessions). 隧道会话中调试 Node.js 脚本时, 电脑仍经局域网连接手机的中继端口 8348, 因此监听范围要设为局域网; 插件按开发连接的对端地址放行这台电脑的中继连接 (经 adb forward 的回环地址除外).

通用 DAP 客户端 (Neovim nvim-dap, JetBrains IDE 的 LSP4IJ 等) 用前两种方式, 配置示例见 调试脚本.

安全#

插件在设计上尽量收窄可以调试本机脚本的范围. 连接后, 电脑可以在本机运行脚本并读取其中的变量, 因此只允许你信任的电脑.

  • 受保护的入口: 调试服务与激活入口都受 AutoJs6 插件权限 (org.autojs.permission.PLUGIN) 保护, 其他应用无法直接调用; 插件在插件中心默认不启用.
  • 监听范围: 默认只监听本机回环地址 (127.0.0.1), 电脑只能经 adb forward 或开发连接隧道到达, 这些连接不需要确认.
  • 局域网的手机确认: 监听局域网时, 一台电脑第一次 launch / attach 之前, 手机询问 "允许这台电脑连接吗?":
    • 询问以通知弹出. Android 10 及以上熄屏时亮屏并显示全屏确认页 (Android 14 及以上需要允许插件的 "全屏询问", 未允许时只以普通通知出现); 手机锁定时可以直接拒绝, 允许之前要先解锁. Android 9 及更早直接打开确认页.
    • 没有通知权限, "连接请求" 类通知被关闭, 或系统没有弹出通知 (例如 MIUI / HyperOS 默认关闭新应用的悬浮通知) 时, 打开插件首页, 在最上方待确认的卡片上回答.
    • 允许并记住: 放行这次连接, 并给这台电脑上的调试客户端下发一个配对密钥. 之后带着有效密钥的连接直接放行, 电脑换了 IP 地址也一样.
    • 仅本次: 只放行这一次连接.
    • 拒绝: 结束这次调试. 90 秒内不回答视为拒绝. 同一地址连续失败 3 次会被暂时拦截, AutoJs6 以 toast 提示.
  • 配对密钥: VS Code 扩展与 AutoJs6 JetBrains 插件自动保存密钥 (VS Code 存在机密存储中, 不写进 launch.json). 不会保存密钥的通用 DAP 客户端在 "允许并记住" 之后, 调试控制台会显示一行以 3-Probe Debugger: 开头的提示, 给出 "pairingKey": "..." 写法, 把它抄进调试配置即可, 见 配对密钥与令牌. 手机上只保存密钥的摘要. 密钥要像密码一样保管. 手机不认识的密钥 (已撤销或写错) 不会被放行, 手机会重新询问.
  • 撤销: 在插件的 "已配对的电脑" 中撤销一台电脑, 会结束它打开的会话, 下次连接时手机重新询问; VS Code 扩展收到撤销后也删除它保存的密钥. 在电脑上, VS Code 命令 "忘记手机的调试配对密钥" 删除某台手机的密钥.
  • 令牌模式: 设置中的 "令牌模式" 供无人值守的测试机使用. 开启后每个连接都要在调试配置中带上 token, 手机不再询问, 也不使用已配对的电脑. 令牌为 256 位随机值, 可在设置中查看, 复制或轮换 (轮换不影响已放行的会话); 插件按常量时间比较令牌, 同一地址连续失败会被暂时拦截.
  • 开发连接隧道: 隧道中的调试会话沿用开发连接已有的信任 (例如 VS Code 扩展建立连接时在手机上确认过的设备), 不再另行确认.
  • 日志: 求值的表达式, 变量值与脚本源码不写进普通日志.

调试的影响#

  • 调试服务开启期间新启动的 Rhino 脚本都带调试钩子, 纯 JavaScript 计算会变慢; 调用自动化 API 的脚本影响很小. 关闭调试服务后, 新启动的脚本没有额外开销. 实测数据见 调试脚本.
  • 在 UI 线程上暂停会让应用无响应: 经本插件连接的调试器可以让 UI 线程停下并查看变量, 但暂停默认至多持续 60 秒, 到时自动继续 (调试配置 uiThreadPauseTimeoutMs, 0 为不自动继续), 电脑端与手机通知都会提示.
  • 同时最多 4 个调试会话. 单条 DAP 消息超过 16 MiB 或格式错误时, 只断开出错的连接并在调试控制台说明原因.

常见问题#

必须使用 VS Code 吗?#

不必. 插件实现标准的 Debug Adapter Protocol, 任何 DAP 客户端都能连接; VS Code 扩展额外提供一键调试, 自动端口转发与开发连接隧道.

调试客户端连不上#

  • 确认 AutoJs6 抽屉中 "调试服务" 显示 "运行中".
  • 经数据线连接时, 确认已执行 adb forward tcp:8347 tcp:8347, 客户端连接的是 127.0.0.1:8347.
  • 经局域网连接时, 确认插件的监听范围为 "局域网 (所有网络接口)", 并在手机上回答确认 (通知, 全屏确认页或插件首页的卡片), 见 手机上没有出现配对询问.
  • 修改过端口时, 客户端要使用新端口.
  • Node.js 脚本的调试器经 HTTP 访问中继端口. 电脑设置了 HTTP 代理 (例如环境变量 HTTP_PROXY) 时, 经局域网的请求可能被代理拦下并返回 503, 此时把手机地址加入不走代理的列表 (例如 NO_PROXY).

手机上没有出现配对询问#

询问以通知弹出, 熄屏时亮屏并全屏显示. 没有通知权限 (Android 13 及以上要允许插件发送通知), "连接请求" 类通知被关闭, 或系统没有弹出通知 (MIUI / HyperOS 默认关闭新应用的悬浮通知) 时, 打开插件首页即可在待确认的卡片上回答. 90 秒内未回答视为拒绝, 同一地址连续失败 3 次会被暂时拦截.

能附加到已经在运行的脚本吗?#

可以附加调试服务开启之后开始运行的 Rhino 脚本. 调试服务开启之前已在运行的脚本, 以及已在运行的 Node.js 脚本不能附加; Node.js 脚本需要以调试模式启动, 见 调试脚本.

AutoJs6 被系统结束后, 调试服务没有恢复?#

AutoJs6 被系统结束后, 调试服务在下次打开 AutoJs6 时恢复 (没有锁屏时, 重新打开后数秒内恢复). 手机锁屏时被拉起的 AutoJs6, 以及由定时任务等在后台拉起的 AutoJs6 不会自动恢复调试服务; 这时插件的监听仍在, 电脑端看到 "AutoJs6 不可用", 打开一次 AutoJs6 即可. 为减少被系统结束, 可按插件首页 "保持运行" 一栏的说明设置电池与自启动.

"调试服务" 下方显示 "后台活动受限"#

Android 限制了 3-Probe Debugger 的后台活动, 熄屏或插件在后台时监听可能被停止, 见 插件的警告.
